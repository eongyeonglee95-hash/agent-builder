# 나이별 연금 세금 경고 설계

2026-11-07 설계 초안. 나이를 선택하면 세금의 원인·금액 영향·가능한 다음 행동이 함께 바뀌는 은퇴 화면을 정의한다. 현재 구현은 개인별 3층 수령액의 기준선 초과 안내까지이며, 아래 세액·대안·Agent는 구현 전이다.

## 1. 화면의 역할

기존 받는 시간표 바로 아래, 생활비 카드 위에 **선택한 나이의 세금과 실수령액** 패널을 둔다. 연금탑·그래프·생활비 카드 구조를 유지한다. 선택 연도와 나/배우자/함께 보기 상태를 공유하고, 세금 배지는 이 패널의 해당 사람·원인으로 이동한다.

패널은 다음 순서로 읽힌다.

1. 선택 연도와 두 사람의 나이, 가장 중요한 경고 한 문장.
2. 사람별 예상 연 세금, 세후 월 연금, 생활비 부족액. 계산할 수 없는 값은 필요한 입력과 함께 표시한다.
3. 현재 계획과 수령 대안의 차이, 그 차이가 생긴 이유.
4. 과세 재원·다른 소득 입력, 대안 비교, 계산 근거 보기 중 해당 경고를 해결하는 행동.

기본 숫자는 그래프와 같은 오늘의 돈으로 비교한다. 세금 상세는 그해 명목 금액을 보여주며 전환 기준을 표시한다. 개인 보기의 금액을 부부 생활비와 직접 비교하지 않는다. 함께 보기에서도 세금 판정은 각자 계산한 뒤 합계만 더한다.

## 2. 경고 심각도와 정보 완성도

**기준선 초과는 과세 방식 비교 신호다.** 실제 손해나 생활비 부족을 뜻하지 않으므로 초과만으로 빨간 경고를 켜지 않는다. 정보가 없는 상태를 정상으로 표시하지 않는다.

| 상태 | 판정에 필요한 근거 | 화면 문구 예시 | 바로 할 일 |
|---|---|---|---|
| 정보 확인 · 회색 | 과세제외 원금, IRP 재원, 다른 소득 등 필요한 항목이 누락됨 | 과세 대상 금액을 확인하면 세금을 비교할 수 있어요 | 빠진 항목 입력 |
| 변화 예고 · 파랑 | 계산 범위의 미래에 처음 기준선을 넘거나 세율·수령 조건이 바뀌는 해가 있음 | 이 나이부터 과세 방식 비교가 필요해요 | 해당 나이로 이동 |
| 비교 필요 · 주황 | 확인된 과세 대상액이 기준선을 초과함. 총수령액만 확인되면 ‘초과 가능성’으로 구분 | 종합과세와 분리과세를 비교해 보세요 | 두 방식 비교 |
| 생활비 부족 · 빨강 | 계산 가능한 세후 가구 연금이 입력한 생활비보다 작음 | 세금을 반영하면 월 생활비가 부족해요 | 부족액·수령 대안 확인 |
| 수령 조건 점검 · 빨강 | 계좌별 자료로 연금수령 요건·수령한도 위반을 판정함 | 이 인출 계획에는 연금외수령 과세가 적용될 수 있어요 | 해당 계좌·연도 확인 |
| 확인 범위 내 특이사항 없음 · 중립 | 해당 판정에 필요한 자료가 갖춰졌고 위 조건이 없음 | 입력한 범위에서는 추가 점검 사항이 없어요 | 계산 범위 보기 |

‘정보 확인’은 다른 경고와 함께 존재할 수 있다. 확인된 연금저축만으로도 기준선을 넘었다면 주황 경고를 유지하고, IRP 재원 미확인은 별도로 표시한다. 총세액을 계산할 수 없으면 전체 세후 연금·생활비 부족액을 확정하지 않는다. 이미 세전 연금부터 부족하면 그 사실을 별도 표시한다.

‘현재 세법을 미래에 적용한 예상’은 공통 가정 표시이며 매년 반복되는 빨간 경고로 쓰지 않는다. 기준선까지 남은 금액 또는 초과 금액은 보여주되, 임의의 비율을 법정 위험 구간처럼 만들지 않는다.

## 3. 나이와 계획에 반응하는 동작

- 그래프를 누르거나 연도 조절기를 움직이면 해당 연도의 경고·세금·실수령액이 함께 바뀐다. 이동 중 모달·토스트를 연속으로 띄우지 않는다.
- 그래프 아래 얇은 사건 띠에 첫 초과, 연령 세율 변화, 첫 생활비 부족, 수령 종료를 표시한다. 연속된 같은 원인의 경고는 구간으로 묶는다. 표시할 사건은 실제 계산 결과에서 만든다.
- 기준선 초과 경고에는 선택 연도의 초과액과 ‘첫 초과 나이’를 구분해 표시한다. 과세 재원 미확인 시에는 ‘총수령액과 기준선의 차이’, ‘확인한 범위에서 첫 초과 가능 시점’으로 표시한다. 선택 연도가 달라도 첫 초과 사실을 새로 발생한 사건으로 취급하지 않는다.
- 납입액·개시 나이·수령 기간을 바꾸면 전체 연도를 다시 계산한다. 선택한 나이는 유지하며, 이전 결과와 새 결과가 섞인 상태에서 금액을 보여주지 않는다.
- 진행 중 입력의 늦은 응답은 폐기한다. 최신 계획·자료·규칙 버전이 모두 맞는 결과만 표시하며, 계산 실패 시 이전 금액에 ‘이전 계산’ 표시를 붙이고 적용을 막는다.
- 나이를 움직이는 동안은 준비된 연도별 결과를 읽는다. 언어모델 호출은 필요하지 않다. 키보드 조절을 지원하고 보조기기 안내는 선택 확정 후 요약 한 번으로 제한한다.
- 금액 숨김은 패널뿐 아니라 초과 시점, 경고 띠, 설명, 접근성 문구에 포함된 금융 정보를 함께 숨긴다. 색 외에 아이콘과 상태 문구를 사용한다.

## 4. 세금이 얼마나 늘었는지의 비교 기준

‘세금 증가’ 하나로 묶으면 원인이 다른 숫자가 섞인다. 아래 지표를 이름과 기준까지 같이 표시한다.

| 지표 | 비교 기준 | 용도 |
|---|---|---|
| 예상 연 세금 | 해당 사람·연도의 선택 과세 방식 | 그해 부담 규모 |
| 전년 대비 세금 변화 | 같은 계획의 바로 전 연도 | 연령·수령액·과세 방식 변화 설명 |
| 현재 계획 대비 세금 차이 | 같은 연도·같은 사람·같은 가정의 저장 계획과 비교안 | 수령 계획 변경 효과 |
| 원천징수 대비 정산 차이 | 최종 예상 세액에서 그 소득 범위의 원천징수액을 차감 | 추가 납부 또는 환급 예상 |

원천징수 실적이 없으면 ‘원천징수 가정 대비’로 표시한다. 연령별 원천징수율을 최종 세율로 확정하거나, 그 차이를 기준선 초과로 인한 확정 추가세금이라고 부르지 않는다. 전년 대비와 계획 대비의 기준이 없으면 0원 대신 비교 불가를 반환한다.

세액 비교는 명목 금액으로 계산하고, 생활비와 비교할 때 같은 기준 연도의 구매력으로 환산한다. 기준선에는 물가를 임의로 적용하지 않는다. 과세 방식·연령·수령액이 동시에 바뀌면 해당 원인을 모두 표시하며 검증하지 않은 요인별 금액 분해는 만들지 않는다.

## 5. 과세 재원과 계산 범위

현재 `Row.items`에는 사람·층·월 명목액·월 실질액이 있고, 세금 안내는 3층 명목 월액을 연액으로 환산한다. 층만으로 과세 재원을 판정할 수 없으므로 계좌별 원천을 추가해야 한다.

필수 입력은 상황에 따라 점진적으로 요청한다.

- 계좌별 소유자, 연금 종류, 세액공제 원금·과세제외 원금·퇴직금 이체분·운용수익과 각각의 자료 기준일. 미확인은 0원과 구별한다.
- 최초 수령 가능 시점, 실제 수령 연도, 계좌 평가 기준액, 적용 가능한 상품 약정과 연금수령한도. ‘연금수령연차’와 ‘연금실제수령연차’를 각각 보관한다.
- 공적연금 과세 대상 부분, 다른 종합소득과 공제, 퇴직금 재원에 대한 이연퇴직소득세 자료. 전체 잔고의 고정 비율을 매년 과세액으로 반복 사용하는 방식은 피하고 법정 인출 순서에 따라 남은 재원을 갱신한다.
- 원천징수 실적 또는 명시적 가정, 소득별 적용 연도. 미래 소득 미입력을 ‘평생 다른 소득 없음’으로 바꾸지 않는다.

연액은 실제 계획의 해당 연도 지급액을 합산한다. 월액 × 12는 12개월 동일 지급 가정이 맞는 경우에만 사용하며, 연중 개시·종료 또는 비정기 인출을 지원할 때는 지급 일정도 입력받는다.

국세청은 사적연금의 과세제외 재원·이연퇴직소득·세액공제 및 운용수익을 구분하며, 연령별 원천징수와 기준선 초과 시 과세 선택을 별도로 안내한다. 구체적 적용 규칙은 [TAX_RULES](TAX_RULES.md)와 버전이 있는 YAML을 원천으로 한다. [국세청 연금소득 원천징수방법](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7888&mi=6452), 2026-11-07 확인.

### 비교 계산의 일관성

사적연금 `Y`의 분리과세액만 다른 모든 소득을 포함한 종합소득 총세액과 직접 비교하면 안 된다. 두 방식 모두 동일한 다른 소득·공제·지방소득세 범위를 포함해 비교한다.

- 종합과세안 = 해당 방식에서의 전체 종합소득 세액 + 별도 과세되는 다른 재원의 세액.
- 분리과세안 = 사적연금 Y를 제외한 소득의 세액 + Y의 분리과세액 + 별도 과세되는 다른 재원의 세액.
- 법적으로 선택 가능한 방식만 비교하고, 같은 소득을 양쪽에서 중복 과세하거나 제외하지 않는다. 공제·세액공제도 각 방식에서 다시 판정한다.
- 다른 소득을 포함한 총세액은 ‘과세 방식 비교’에 쓴다. 연금만 그리는 그래프에서는 같은 조건의 비연금 소득만 있을 때 세액을 기준으로 연금 때문에 달라진 세액을 계산해 차감한다. 소득별 세액을 표시한다면 배분 방식을 명시하고 합계가 총세액과 일치해야 한다.
- 개인별 연금 세액을 계산한 뒤 부부 합계를 만든다. 필요한 재원이 빠지면 전체 세후 합계는 null이며, 계산 가능한 부분은 ‘개인연금만’ 등 범위를 붙인다.
- 건강보험료는 세금과 별도다. 기존 생활비에 입력한 건강보험료를 다시 차감하지 않는다. 보험료 추정이 미구현이면 세후 표시가 보험료까지 반영한 가처분소득처럼 보이지 않게 한다.

금액은 정수 원과 Decimal로 계산한다. 원천징수·연간 정산·지방세별 절사 및 반올림을 공식 근거로 확정하고 테스트한다. 그 전에는 신고 세액과 일치한다고 표시하지 않는다. 적용 연도, 법령 시행일, 확인일, 규칙 버전을 저장한다.

자료가 부족할 때 사용자가 선택한 ‘전액 과세 대상 가정’ 같은 가상 조건은 비교안 안에서만 계산한다. 실제 계획의 사실로 저장하거나 가구 전체 세금의 상한이라고 설명하지 않는다. 확인된 금액 범위가 없으면 임의의 세금 범위도 만들지 않는다.

## 6. 수령 대안과 제안 기준

선택한 나이는 결과를 살펴보는 시점이다. 그해 숫자만 줄이는 대신 현재부터의 전체 계획을 비교한다. 이미 수령한 기간은 고정하고, 바꿀 수 있는 미래 조건만 후보로 만든다.

후보는 현재 계획 유지, 개시 시점 조정, 수령 기간 조정, 허용되는 연간 수령액 배치다. 상품 약정·연금수령 요건·잔액·납입 일정·연금수령한도를 만족하는 경우만 제시한다. 현금 주머니로 부족분을 채우는 안은 현금흐름 연결이 구현된 뒤 비교한다.

현재 엔진은 사람별 `private_start_age`가 퇴직·개인·추가연금에 공통 적용되고, 수령 종료는 공통 가정에 연결되어 있다. ‘개인연금만 조정’하려면 계좌/재원별 수령 설정을 먼저 분리해야 한다. 공통 설정을 바꾸고 개인연금만 바뀐 것처럼 제시하지 않는다.

대안 표에는 같은 연도의 세액·세후 월액뿐 아니라 다음을 함께 표시한다.

- 같은 비교 종료 연령까지의 생활비 부족 연수와 부족액 합계.
- 동일 기준 연도로 환산한 누적 세후 수령액·세금, 비교 종료 시점의 잔액과 이후 수령 일정.
- 현재 계획 대비 달라진 조건, 바뀌지 않은 수익률·물가 가정, 계산 가능한 자료 범위.

단순히 늦게 받아 세금이 비교 범위 밖으로 밀린 안을 절세 최적안으로 선정하지 않는다. 미래 수익률과 생존 기간은 가정으로 남긴다. 기준이 충돌하면 ‘생활비 부족이 적은 안’, ‘비교 기간의 세금이 적은 안’을 나란히 제시한다. ‘입력한 조건과 비교한 후보 중’이라는 범위를 명시하고 적용은 사용자가 선택한다.

## 7. 세금 Agent와 데이터 계약

계산 함수가 경고 코드, 근거 수치, 유효한 후보, 비교 결과를 만든다. Agent는 그 결과로 원인·영향·대안의 장단점과 필요한 입력을 설명한다. 기존 Claude 실행 엔진과 출력 검증 경계를 유지한다. 투자 비율·종목은 변경하지 않는다.

제안하는 계산 결과 계약은 다음과 같다. 화면과 Agent는 같은 스냅샷을 사용한다.

| 필드 | 의미 |
|---|---|
| snapshot_id / plan_version / data_version / rule_version | 계획·자료·규칙의 일치 확인 |
| year / person / age / base_year | 선택 시점·소유자·구매력 기준 |
| coverage / missing_fields / assumptions | 계산 범위, 미확인 값, 명시적 가정 |
| gross_annual_nominal / taxable_private_annual | 총수령액과 과세 대상액 구분 |
| methods / pension_tax_annual / net_monthly_real | 방식별 비교, 연금 귀속 세액, 같은 기준의 실수령액 |
| alerts / events | 경고 코드·심각도·확실성·근거 필드·행동, 연도별 변화 |
| comparisons / baseline_snapshot_id | 현재 계획 대비 및 전년 대비 차이와 비교 기준 |
| sources / effective_year / checked_on | 법령·규칙 출처와 적용 시점 |

확실성은 verified_inputs / assumed / incomplete처럼 별도 필드로 두며, 미래 결과 자체가 확정되었다는 뜻으로 쓰지 않는다. 경고는 person·year·code로 식별하고 동일 원인의 중복을 묶는다. 누락 값에는 null을 사용한다.

Agent는 금액을 직접 계산하거나 부족한 자료를 추정해 채우지 않는다. 설명 숫자·소유자·연도·범위·부호가 스냅샷과 일치하는지 출력 전 검증한다. 설명 실패 시 규칙 기반 문장과 계산 표를 유지한다. 나이 이동마다 호출하지 않고, ‘이유 자세히’ 요청을 현재 스냅샷 기준으로 처리한다.

시나리오 미리보기는 저장하지 않는다. 적용할 때 현재 버전을 다시 검사하고 바뀌는 사람·계좌·연도와 기존 계획 대비 차이를 보여준다. 변경 내역과 수락·거절·사유를 기존 결정 기록 흐름에 연결한다. 다른 세션에서 자료가 바뀌면 이전 비교안을 자동 적용하지 않는다.

## 8. 구현 단계와 검수 조건

| 단계 | 구현 범위 | 완료 조건 |
|---|---|---|
| 1. 동적 경고 | 현재 자료로 가능한 초과 가능성·미확인 항목·첫 초과 사건과 연동 패널 | 나이/사람/숨김 상태 일치, 실제 세액이나 최적안으로 오인할 문구 없음 |
| 2. 세금 계산 | 재원별 입력·법정 인출 순서·과세 방식 비교·원천징수와 정산·세후 표시 | 공식 사례와 경계값 테스트, 누락 자료의 부분 계산, 전체 합계와 범위 일치 |
| 3. 수령 대안 | 계좌별 수령 계획·제약 검증·같은 기간의 비교·적용 전 차이 확인 | 생활비·잔액·기간 밖 지급까지 비교, 불가능한 대안과 소급 변경 차단 |
| 4. 설명 Agent | 검증된 결과로 원인과 대안 설명, 결정 기록 연결 | 숫자/소유자/연도 검증, 오류 시 기본 설명 유지, 승인된 계획만 저장 |

예정 담당 경로는 `tools/pension_tax.py`·`rules/pension_tax.yaml`·은퇴 API·`web/src/retirement/TaxImpactPanel.tsx`와 전용 스타일/테스트다. 기존 `pension_tax_notice.py`와 배지는 1단계에서 호환하고, 공통 파일은 연결부만 수정한다. 실제 구현 착수 때 WORK_AREAS와 DEV_HANDOFF를 다시 확인한다.

필수 검수 사례:

1. 기준선 바로 아래/동일/바로 위, 같은 사람의 여러 계좌 합산, 부부 합산 판정 금지.
2. 연령 세율 경계 전후, 종신형 적용 가능 여부, 퇴직연금 실제수령연차 경계와 수령한도 연차의 구분.
3. 과세제외 원금이 큰 연금, 개인납입이 섞인 IRP, 국민연금과 연금보험의 과세 범위, 인출 순서와 원금 소진.
4. 다른 소득·공제에 따라 종합/분리과세의 유불리가 바뀌는 경우, 낮은 세액과 낮은 원천징수액의 구별, 누락을 0으로 계산하지 않음.
5. 물가 가정에 따라 오늘 돈만 달라지는 경우의 기준선 판정, 명목/실질 금액의 일관성, 음수 차액·환급 표시.
6. 빠른 연도 이동·계획 변경의 응답 순서, 금액 숨김·키보드·360/390/1440px 표시, 경고 묶음과 중복 안내 방지.
7. 절세안 때문에 생활비 부족이 늘어나는 경우, 비교 기간 밖으로 수령이 밀리는 경우, 계좌 잔액 부족·약정 위반 대안 제외.
8. 미리보기/취소의 저장 없음, 버전 충돌 재계산, Agent 숫자 오류·실패 시 기본 설명 유지.

이번 설계 검토는 기존 코드·공식 안내와 범위를 대조한 문서 검토다. 제품 동작·디자인 구현·세액 계산·실모델 연결 테스트 완료를 의미하지 않는다.
