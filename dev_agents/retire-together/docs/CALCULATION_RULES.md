# CALCULATION_RULES — 모든 공식

최종 갱신: 2026-10-26
원칙: 여기 있는 공식은 전부 코드(순수 함수)로 구현하고 단위 테스트를 둔다. LLM은 이 공식을 실행하지 않고, 결과 수치만 받아 설명한다. 기본 가정값은 사용자가 바꿀 수 있는 설정이며, 바뀐 값은 DECISIONS.md에 기록.

## 1. 비중·편차 (PoC)
- 자산군 평가액 A_i = Σ(보유수량 × 현재가) (해당 자산군 종목 합)
- 총 평가액 T = Σ A_i + 예수금(현금)
- 현재 비중 w_i = A_i / T
- 목표 비중 t_i (전략 YAML, Σ t_i = 1)
- 편차 d_i = w_i − t_i (퍼센트포인트)
- 발동: |d_i| > θ (기본 θ = 0.05, 2026-10-26 사용자 확정) 인 자산군이 하나라도 있으면 발동. 상대 기준 옵션: |d_i| / t_i > 0.25
- 목표 비중 t_i의 원천은 `rules/strategies.yaml`

## 2. 재배분 금액·수량
- 목표 금액 G_i = t_i × T
- 거래 금액 Δ_i = G_i − A_i (양수 매수, 음수 매도)
- 현금흐름 우선안: 신규 납입 C가 있으면 T' = T + C 로 G_i 재계산 후, Δ_i ≥ 0 인 자산군만 매수로 채움. 이후에도 |d_i| > θ 인 자산군만 매도 포함안 제시
- 수량 q_i = floor(|Δ_i| / 종목 현재가) (정수 주). 자산군에 종목이 여럿이면 사용자 매핑표의 비율로 배분
- 최소 거래 금액 미만(기본 10만원)은 생략
- 매도 후 매수 순서로 주문표 작성(예수금 부족 방지). 예수금 부족 시 매수 수량을 가용 현금에 맞춰 축소하고 표시

## 3. "왜 지금" 설명용 수치
- 가정 하락장: 주식형 자산군 −30%, 장기채 +5%, 중기채 +2%, 금 0%, 원자재 −10%, 현금 0% (기본값, 설정 가능)
- 현재 비중 손실 L_now = Σ w_i × shock_i × T
- 목표 비중 손실 L_target = Σ t_i × shock_i × T
- 설명에는 L_now, L_target, 차이(L_now − L_target)와 가장 편차 큰 자산군을 넘긴다

## 4. 4층 연금 수령액 (3단계)
- 1층 국민연금: 공단 예상연금액(월, 현재가치) 입력 → 수급 개시 연령부터 물가상승률 π로 연 상승. 법정 개시 나이(출생연도표)보다 앞당기면 1년당 `national.early_reduction_per_year`(6%) 감액, 늦추면 1년당 `late_increase_per_year`(7.2%) 증액, 최대 5년(`rules/pension.yaml`). 선택지 표(조기 5년~연기 5년)의 손익분기 나이 = 정상 수령과 누적액이 같아지는 나이(오늘 돈, 둘 다 물가 연동이라 단순 비교; 수익률·세금 미반영): 조기 e년 → 법정나이 + e·f/(1−f), 연기 d년 → (법정나이+d) + d/(f−1). 앱은 어느 쪽도 추천하지 않는다(2026-11-02)
- 유족연금 대충 보기: 사망자 월액 × 가입기간 비율(10년 미만 40%·10~20년 50%·20년 이상 60%, 기본 60%). 남은 사람도 노령연금이 있으면 ‘본인 + 유족연금×30%’와 ‘유족연금만’ 중 큰 쪽을 표시. 부양가족연금액·실제 가입기간·세금·시간표 반영은 하지 않는다(2026-11-02 사용자: “시뮬레이션 대충”)
- 2층 퇴직연금: DB = 퇴직 직전 평균임금 × 근속연수 (사용자 입력) / DC·IRP = 적립금 FV
- 3층 개인연금·4층 추가연금(세제비적격 연금보험·ISA): 적립금 FV. 4층은 같은 공식으로 월액을 내되 **기본 합계(total_*)·부족액·충당률에는 넣지 않고 `extra_real`/`extra_nominal`·`coverage.with_extra`로 따로** 돌려준다. 화면은 ‘월급으로 나눠 쓰면 (1~3층+4층) / 목돈으로 두면 (적립금 그대로)’ 두 숫자를 나란히 보여 주고 어느 쪽도 추천하지 않는다 (2026-11-02 사용자: 4층은 노후 목돈이 될 수도 있어 성격을 열어 둔다)
- 적립금 FV = 현재 잔고 × (1+r)^n + 연 납입 × [((1+r)^n − 1) / r] (r 연 수익률, n 개시까지 연수)
- 연금 월 수령액(확정기간형) = FV × r_m / (1 − (1+r_m)^(−m)) (r_m 월 수익률, m 수령 개월 수)
- 가구 월 수령액 = Σ(배우자별 각 층 월 수령액), 연도별로 개시 시점이 달라 계단형
- 기본 가정(2026-10-26 사용자 확정. 원칙: 연금 종류별 제도 기본값을 두고 사용자가 바꿀 수 있다. 변경은 DECISIONS 기록): 명목 수익률 r = 5% (연금계좌 자산배분형), 물가 π = 2%
- 개시·수령 기간은 층별 기본값 (기간이 아니라 종료 나이로 관리):
  - 국민연금: 출생연도별 수급 개시 연령(기본 65세), 종신 → 시뮬레이션은 90세까지
  - 퇴직연금(DC·IRP)·연금저축: 개시 55세, 확정기간형 종료 90세(=35년). 제도상 최소 수령 기간 10년
  - ISA→연금계좌 이전분: 연금저축과 동일
  - 은퇴 목표 나이는 사용자 입력(컨셉 이미지 62세)
- 구현(RETIRE-01, 2026-11-02): `tools/pension.py`, 기본값 원천 `rules/pension.yaml`, 화면은 워크북 '은퇴' 시트. 구현하면서 정한 계산 방식:
  - 납입은 은퇴 나이와 개시 나이 중 이른 쪽까지만. 그 뒤 개시까지는 수익률로만 불어난다: FV = 잔고×(1+r)^n + 연 납입×[((1+r)^k − 1)/r]×(1+r)^(n−k), k = 납입 연수
  - DB형(2026-11-02 근속 입력 추가): 월급은 최근 3개월 **세전** 급여 총액 ÷ 3. 기존 회사 확인금액 방식은 은퇴 때 퇴직금(오늘 돈) = 지금 퇴직금 + 월급 × max(은퇴 나이 − 만 나이, 0)를 유지한다. 사용자가 ‘입사일로 계산’을 선택하면 기준일 직전까지 실제 근속일수 = 기준일 − 입사일, 예상액 = round(월급 × 근속일수 ÷ 연 환산 일수). 연 환산 일수·최소 근속연수는 `rules/pension.yaml`의 `db`가 원천이다. 최초 근속 1년 미만은 현재 예상 지급액 0원으로 표시하며 계속 재직한 미래 시점은 다시 판정한다. 두 방식의 금액을 더하지 않고 회사 확인금액 원본은 방식 전환에도 보존한다.
  - 근속 미리보기는 저장 없이 같은 순수 함수(`db_estimate`)로 계산한다. 기준일은 조회한 날짜, 미래 시점은 그 날짜의 연 단위 기념일(윤일은 해당 월 말일). 실제 입사일과 달력상 년·개월 및 총일수를 함께 표시하며 은퇴 목표는 여전히 나이 차이의 연 단위 추정이다. 매 조회 시 기준일이 갱신되고, 은퇴 나이·현재 나이 미입력 시 현재 예상액만 반환한다. 미래 입사일·잘못된 날짜는 거절하며 자동 방식의 입사일/급여가 빠지면 저장하지 않는다. 현재 DB 예상액은 계좌 잔액과 계속 분리한다.
  - DB 자동 방식은 재직 중·주 15시간 이상·중간정산/근속 제외기간 없음 가정의 **간편 추정**이다. 월 평균급여는 법정 30일분 평균임금의 근사이며 상여·연차수당 및 통상임금과의 비교는 미반영. 중간정산·퇴직 이력이 있으면 회사 확인금액 방식을 안내한다. 법정식은 1일 평균임금 × 30 × 근속일수 ÷ 365, 1일 평균임금은 퇴직 전 3개월 임금총액 ÷ 해당 역일수이며 통상임금보다 적으면 통상임금을 사용한다. 근거: [고용노동부 퇴직금 계산기](https://1350.moel.go.kr/home/hp/retirementpaycal/retirementpaycal.jsp), [퇴직금 및 평균임금 산정공식](https://moel.go.kr/faq/faqView.do?seqRepeat=89) (2026-11-02 확인).
  - DB의 임금은 물가만큼만 오른다고 가정한다(승진·호봉 미반영, 추정 오차의 방향은 보장하지 않음). 은퇴 때 명목금액 = 오늘 돈 × (1+π)^(퇴직까지 연수)를 IRP로 옮겼다고 보고 개시 나이(퇴직이 더 늦으면 퇴직 나이)부터 확정기간형으로 받는다. 퇴직소득세 미반영.
  - 사적연금 개시 기본값 = max(55, 은퇴 나이). 개시 < 55 또는 수령 기간 < 10년이면 계산하지 않고 이유를 보여 준다
  - 화면 금액은 '오늘 돈' = 명목 ÷ (1+π)^(경과 연수). 국민연금은 오늘 돈으로 일정, 사적연금은 명목 일정이라 오늘 돈으로는 줄어든다
  - 계산 단위는 1년(기준 연도 만 나이 + 경과 연수). 마지막 해는 종료 나이 직전
  - 화면 수령 기간은 각 실제 스트림의 종료 나이 − 개시 나이. 예: 60세부터 90세 직전까지 30년. 이미 개시 나이를 지났으면 현재 나이가 개시 기준, DB는 실제 퇴직/개시 중 늦은 시점. 부부·DB/DC·개인연금 기간을 하나로 고정하지 않는다. 국민연금의 계산 범위를 확정 수령 기간으로 표기하지 않는다.
  - 적립금은 장부의 노후 주머니. 층은 (1) 자산에 사용자가 고른 `pension_layer`(2·3·4) → (2) 계좌 목록의 layer → (3) 계좌 이름(IRP·퇴직·DC → 2층, 연금저축 → 3층, 연금보험·ISA·추가연금 → 4층, 나머지 → 3층) 순. 세제비적격(일반·변액연금보험)은 4층, 세제적격(연금저축·IRP 개인납입)은 3층 (2026-11-02 사용자 결정)
  - 배우자 은퇴 나이 기본값 = 나와 같은 해. 국민연금 개시 기본값 = 출생연도(기준 연도 − 만 나이) 표
  - 생활비 비교: 은퇴(나 기준) 뒤 해마다 가구 월 수령액(오늘 돈) − 월 생활비. 부족한 해 수와 부족액 합계(×12)
  - 항목별 생활비 목표(2026-11-02): 월 식비 = 1인 한 끼 금액 × 인원 × 하루 끼니 × 월 일수. 주택 보유세 월 예산 = 연간 입력액 ÷ 12를 원 단위 반올림(0.5 올림). 목표 = 식비 + 보유세 월 예산 + 용돈·관리비/교통/통신·민간보험·병원/약값·건강/장기요양보험·비정기 비용·기타 월액. 금액은 음수가 아닌 정수 원, 인원/끼니는 1~10, 일수는 1~31이며 월 합계는 기존 목표 입력 한도 안에서 검증한다. 초안의 원천은 `rules/pension.yaml spending_budget_template`이며 적정생활비 통계나 세금 자동 추정이 아닌 검토용 예산이다. 명시적으로 적용할 때 서버가 항목에서 합계를 다시 계산해 항목·목표를 버전 검사 후 함께 저장한다. 취소는 저장하지 않으며, 이후 목표만 직접 수정하면 보관한 항목이 목표를 덮어쓰지 않는다. 오늘 돈·부부 합계의 지출 목표이고 연금소득세 차감은 아직 반영하지 않는다.
  - 생활비의 물가 환산(2026-11-02 사용자 요청): 기준 연도 현재의 월 생활비 C, 물가상승률 π, 경과 연수 n에 대해 해당 해의 명목 월 생활비 = round(C × (1+π)^n). 은퇴 첫해 n = max(나의 은퇴 나이 − 현재 나이, 0). 이미 은퇴했으면 올해 기준, 월 생활비 미입력은 계산하지 않고 0원 입력은 0원으로 유지. 일 단위 예상 은퇴일은 없으므로 연 단위로 계산한다. 은퇴 첫해 생활비 카드는 개인 보기에서도 가구 목표이며, 나의 은퇴 시점을 기준으로 명시한다.
  - 명목 비교는 해당 해의 명목 수령액 − 명목 생활비. 오늘 돈과 그해 돈을 섞거나 기존 실질 월 수령액에 물가를 두 번 반영하지 않는다. 화면 게이지는 오늘 돈 기준으로 층별 월액 / 가구 생활비 C × 100(전체는 합계 / C). 층별 목표를 임의 배분하지 않는다. C 미입력/0원·은퇴 전은 게이지 없음, 100%를 넘는 수치는 유지한다. 4층 미지원 금액은 충당률에 포함하지 않는다.
  - 받는 시간표의 누적 영역 그래프는 각 연도 국민·퇴직·개인연금 **월 수령액**을 아래부터 쌓은 것이다(누적 수령 총액 아님). 기존 서버의 오늘 돈 금액을 연 단위 계단으로 연결하고, 가구 전체·필수 입력 완비인 경우에만 은퇴 이후 부부 생활비 목표선을 표시한다. 개인 보기·금액 숨김에서는 목표선을 표시하지 않는다. 4층은 기본 합계 밖(extra로 별도), 국민연금은 종신이며 그래프 끝은 화면 계산 범위다.
  - 현재 계좌 적립금은 등록한 2·3·4층 잔액만 합산한다. 국민연금 예상 월액·앞으로 납입할 금액·미래 DB 퇴직금은 현재 계좌 잔액에 더하지 않는다. 현재 DB 퇴직금(지금 퇴직해도 받는 확정 금액)은 전체 ‘지금 모인 돈’과 2층 적립금에 합산하되 내역에서 ‘계좌 x · 확정 퇴직금(DB) y’로 구분한다(2026-11-02 사용자 결정). 퇴직금이 IRP로 입금되면 DB 입력을 0으로 두어 중복을 막는다. 석탑의 고정 색은 연금 종류만 구분하며 잔액·준비율에 따라 채워지지 않는다. 실제 생활비 기여율은 층별 항목의 게이지와 숫자로 표시한다.
  - 아직 넣지 않은 것: §5 세금·연금수령한도, ISA, 현금 주머니로 메우는 기간

## 6. 부동산 갈아타기 (4단계)
### 6-M. 갈아타기 비교 구현 (2026-11-02, `tools/property_move.py`)
- 계획은 부부/나/배우자 범위별로 저장. 사용자가 매도 대상으로 선택한 집만 포함, 개인 범위는 집·연결 대출·보증금 각각의 해당 지분을 사용한다. 목표 아파트 가격은 집 전체 가격이다.
- 매도 후 자금 S = 선택 집 평가액 합계 − 연결 대출 − 반환 보증금 − 입력한 매도세금·비용. 음수도 유지. 산 가격을 시세 대용으로 쓴 경우 재확인 필요를 표시한다.
- 자기자금 E = S + 이사에 배정한 현금·투자자산 현재액 C. 연금·현금 주머니 전체를 자동 포함하지 않는다. C 미입력은 계산 대기이며 0원과 구별한다.
- 총 필요자금 T = 후보의 계획 매수가 + 입력한 취득세·중개·이사비. 비용 미입력 시 0으로 잠정 계산하되 ‘비용 미입력’으로 명시. 세금 자체는 자동 산정하지 않는다.
- 현재 부족액 G = max(0, T − E − 추가 대출 가정 L). L은 모은 돈과 별도 표시하며 승인 가능액이 아니다. 자기자금 준비율 = min(100, max(0, E / T × 100)).
- 남은 개월 N = max(0, (목표연도−현재연도)×12 + 목표월−현재월). 예상 추가저축 F = 월 저축 × N, 목표일 부족액 = max(0, G−F), 필요한 월 저축 = ceil(G / N), N=0이면 월 저축 역산 없음. 수익률·가격 상승·물가 가정은 넣지 않는다.
- 후보 비교: 같은 자금 조건에서 매수가/총 필요자금/부족액 비교. ‘목표보다 저렴’은 계획 매수가 차이일 뿐 저평가·매수 추천이 아니다. 가격 없는 후보는 계산하지 않는다.
- 격차 D = 목표 집 가격 − 매도 대상 집 평가액 합계(둘 다 집 전체, 비용·대출 제외). 갈아타기 추적의 기준 숫자는 집값이 아니라 D의 변화다(`price_gap`).
- 호가 vs 과거 실거래(`asking_vs_trades`): 같은 단지·면적 실거래(최대 36개월)의 건수·최신 거래·중간값·최저·최고와, 호가 − 최신 거래, 호가 − 중간값(원·%)만 계산한다. 적정·고평가·매수 시점 판단은 하지 않는다. 호가가 없으면 비교 칸은 비운다.
- 거주 정보(학군·출퇴근·생활·단점)는 사용자가 직접 적는 글이며 자동 조회·점수화하지 않는다.
- 추적 기록: 후보별·날짜별 한 줄(같은 날은 덮어씀). 기록 시점의 목표 집 가격(기준: 실거래·호가·계획 매수가 중 화면이 보여준 것)·우리 집 평가액·D·G를 저장한다. 계획을 저장할 때 가격이 있는 후보는 자동으로 오늘 줄을 남기되, 마지막 줄과 가격·G가 같으면 남기지 않는다. 후보를 지우면 그 기록도 지운다. 기록 간 차이는 저장된 D끼리의 차이이며 예측이 아니다.

### 6-0. 보유 집 지표 (2026-11-02, `tools/property.py`)
- 오른 금액 G = 시세 − 산 가격, 오른 비율 G / 산 가격. 산 가격을 모르면 표시하지 않는다(추정 금지)
- 남는 돈 E = 시세 − 그 집에 연결한 대출 − 세입자에게 돌려줄 보증금. 보증금은 장부에 대출 행으로 함께 저장
- 대출 비율 = 연결 대출 / 시세, 보유 기간 = 산 달부터 기준일까지 꽉 찬 개월
- 시세 출처: 등록 때 묻지 않는다. 최근 12개월 같은 단지·면적 실거래 중 가장 최근 거래 → 없으면 산 가격(‘시세 확인 필요’) → 없으면 0. 출처를 함께 저장해 화면에 표시
- 실거래가: 국토부 아파트 매매 실거래가(공공데이터포털), 같은 시군구·전용면적 ±2㎡, 해제 거래 제외, 최근 12개월. 법정동+지번이 양쪽에 있으면 정확히 일치하는 주소로 식별하여 개명 전후 거래를 연결하고, 필지가 다르면 같은 이름이어도 제외한다. 주소가 부족한 구형 응답은 법정동·단지명(포함 관계, 거래 쪽 이름이 더 짧으면 4글자 이상)으로 비교한다. 조회만으로 저장된 시세는 바뀌지 않는다.
- 호가·매물: 직접 기록과 부동산뱅크 공개 매물 조회를 구분한다. 공개 조회는 법정동·정확한 단지명(주소로 확인한 국토부 신고명 포함)·전용면적 ±2㎡ 기준, 광고 ID 중복 제거, 게시된 매매 총액을 원 단위로 변환한다. 분양가·프리미엄·옵션을 총액에 다시 더하지 않는다. 확인일·조회 시각·출처 원문·부분 조회 여부를 표시하며 건수는 광고 수(같은 집의 여러 광고 가능)다. 읽기 전용·15분 캐시·최대 10페이지, 연결 실패와 조회 결과 없음은 별도다. 호가를 장부 시세·순자산·합계에 자동 반영하지 않는다.
- 전체 매도 요약 = 현재 소유자 범위의 모든 집 등록 시세 합계 − 각각 연결된 대출 − 반환 보증금. 매도세금·중개비 차감 전이며, 가격 미확인 집을 0원으로 간주한 완전 합계를 표시하지 않는다. 자금 계획에서 선택한 매도 대상 합계와 구분한다.
- 추적 평형 선택은 최근 실거래·공개 매물에서 관측한 전용면적의 정수 ㎡ 군으로 묶는다. 조회되지 않은 평형은 직접 입력 가능하며 전체 평형 목록이라고 단정하지 않는다. 공급면적이 있을 때만 공급㎡ ÷ 3.305785를 반올림한 약 평형을 함께 표시한다(전용 84㎡를 임의로 34평형으로 환산하지 않음).
- 개인 보기: 집·대출·보증금 각각 장부 지분(scoped_asset)으로 나눈 뒤 E를 다시 계산. 오른 금액은 집 지분 비율로 나눈다
- 필요 자금 N = P_target × (1 + 취득세율 + 중개수수료율) − (P_current − L_current) − S_cash
- 월 필요 저축 M = N / 개월 수 (수익률 0 가정 단순형) 또는 N × r_m / ((1+r_m)^k − 1) (복리형)
- 갭투자형 필요 자금 = (P_target − 전세가) × (1 + 취득세율 + 중개수수료율) − S_cash
- 분양권+월세 시나리오: 연도별 현금흐름 = −계약금 −중도금(회차) −잔금 −취득세 −월세×12 + (기존 집 매도 시점 유입); 비교 지표는 입주 시점 순자산과 현금 주머니 목표 달성 시점

## 7. 보유 종목 손익 (2026-10-28, Robinhood 'Position'·'Using charts' 참고 — docs/research/ROBINHOOD_DEEP_DIVE.md)
- 평가금액 V = 보유수량 q × 현재가 p. 현재가는 등록한 잔고의 가격, "현재가로 보기"를 켜면 공개 시세
- 넣은 돈(매입금액) B = 등록한 매입금액(캡처·파일·직접 입력). 모르면 비워 두고 **추정하지 않는다**
- 불어난 돈(총 손익) R = V − B, 수익률 R / B. 매입금액을 아는 종목만 더한다. 합계에는 "매입금액을 아는 종목 n개 기준"을 함께 표시
- 오늘 손익 D = q × (p − 전일 종가). 오늘 등락률 = (p − 전일 종가) / 전일 종가. 공개 시세를 받았을 때만
- 비중 = V / Σ V (선택한 범위 안)
- 손익 기여 순위(어제 종가 이후): |D|가 큰 순서. 크게 움직인 종목: |오늘 등락률|이 큰 순서
- 잔고가 오래됨: 오늘 − 기준일 > `rules/holdings.yaml`의 stale_days
- 입금·출금(연금 납입)은 수익이 아니다. 평가금액이 늘어도 넣은 돈이 같이 늘었으면 불어난 돈은 그대로다
