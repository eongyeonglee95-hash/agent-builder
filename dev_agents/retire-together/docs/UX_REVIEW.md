# 둘이서은퇴 사용성 검토안

2026-10-27 · 현재 화면·입력 코드에 대한 기획 검토. 사용자 테스트 결과가 아니며, 검토 뒤 사용자가 개선안 반영을 승인했다. 구현 범위와 검증은 아래 실행 기록을 따른다.

검토 근거: `MASTER_PRD.md`, `web/src/App.tsx`, `forms.tsx`, `stocks.tsx`, `property.tsx`, `local-data.ts`. 현재 템플릿의 소개용 예시와 실제 데이터 연결의 미완료를 구분했다.

## 1. 제품에서 먼저 답해야 할 질문

사용자가 처음에는 “우리 돈이 어디에 얼마 있지?”, 반복 사용에서는 “지난번과 무엇이 달라졌고, 이번에 할 일이 있나?”에 답을 얻어야 한다. 장기 목표는 “부부가 매달 얼마로 은퇴할 수 있나?”, “다음 집까지 무엇이 부족한가?”다.

제안하는 두 사용 과정:

- 첫 사용: 자산 추가 → 내 것/배우자 것/공동 선택 → 캡처·종목·총액 중 선택 → 결과 확인 → 저장 → 홈에서 등록 결과 확인.
- 반복 사용: 홈의 변경/확인 필요 항목 확인 → 해당 자산만 갱신 → 이전과 달라진 점 확인 → 필요한 결정 기록 → 끝.

처음부터 두 사람의 전체 재산과 은퇴 목표를 완성해야 쓸 수 있는 구조를 피한다. 배우자 자료와 수령 정보는 나중에 추가할 수 있어야 한다.

## 3. 첫 사용 과정 제안

### 시작 화면

주 행동은 “첫 자산 추가하기”. 보조 행동은 “예시로 둘러보기”. 예시 보기를 실제 데이터 모드와 같은 무게의 상시 작업으로 배치하기보다, 체험 공간임을 분명히 한다.

별명과 소유자를 최소한으로 묻는다. 배우자를 대신 입력해 관리할 수 있게 하되, 다른 기기 공유·인증과는 구분한다. 성별, 가족 역할, 은퇴 목표는 필요한 기능을 열 때 설명과 함께 추가한다. 이는 현재 스키마 변경이 필요한 제안이며 기존 필드를 즉시 삭제한 것이 아니다.

### 첫 자산 추가

1. 무엇을 추가하나요? 연금 / 주식·ETF / 예금·현금 / 집 / 대출.
2. 누구의 것인가요? 나 / 배우자 / 공동(집 등 지원하는 자산).
3. 어떻게 입력할까요? 캡처 올리기 / 직접 입력. CSV는 추가 방법에 둔다.
4. 앱이 읽은 정보 확인. 불확실한 칸만 강조하고 수정할 수 있게 한다.
5. 저장 후 “연금저축 1개를 등록했어요. 현재 등록한 금액은 …원입니다.”로 끝낸다. 다음 자산 추가는 선택이다.

전체 보유 금액만 입력한 계좌도 허용한다. 이후 종목 상세를 넣으면 같은 계좌에 연결한다. 총액과 종목 합계가 다르면 차이를 보여주고 어떤 값을 쓸지 확인한다. 조용히 합산하거나 덮어쓰지 않는다.

## 4. 화면별로 줄이고 분명히 할 것

### 홈

상단에는 현재 등록한 자산/부채와 자료 완성 상태, 이번에 확인할 행동을 둔다. 은퇴 정보가 없으면 임의의 월 수령액이나 가능 시점을 제시하지 않는다. “은퇴 목표”와 계산한 “목표 달성 전망”을 구분한다.

예시 문장(금액은 화면 설명용): “배우자의 연금 정보가 아직 없어요”, “지난 확인 이후 수량이 바뀌었다면 잔고를 갱신해 주세요”. 데이터가 없는 사용자를 이상적인 가구와 비교해 경고하지 않는다.

### 주식

첫 화면은 평가금액 / 매입 대비 손익 / 정보 기준 시각 / 보유 종목. 종목을 누르면 평단가·수량·시세·손익·해당 뉴스가 연결된다. 수수료·세금·환율 반영 범위를 상세에서 확인할 수 있게 한다.

자료가 오래됐거나 조회가 실패하면 이전 가격과 그 시각을 유지한다. 데이터가 없는 값을 0으로 표시하지 않는다. 해외 주식은 원화 평가와 현지 통화 수익을 구분해야 하며, 대상 시장은 아직 미확정이다.

뉴스는 최근의 보유 종목 관련 소식부터 보여준다. “어제”의 기준 시간대와 원문 발표 시각을 정의하고 수집 시각과 구분한다. 관련 없는 동명 회사 기사, 중복·재송고 기사, 오래된 기사 재노출을 다룬다. 방향 설명은 근거와 불확실성을 포함하고, 기사 분류만으로 자동 매매 행동을 만들지 않는다.

### 연금·리밸런싱

사용자는 먼저 “이번에 점검이 필요한가?”를 본다. 이어 이유 → 기존 규칙과의 차이 → 필요한 입력 → 검토용 주문표 순서로 펼친다. 전략 이름·자산군·풀 설정을 처음부터 선택하게 하지 않는다.

“계획 수락”, “증권사에서 직접 주문”, “실제 체결 확인”을 별개로 둔다. 계획을 보았다는 이유만으로 보유 수량이 바뀌면 안 된다. 부분 체결·미체결은 확인과 수정 경로가 있어야 한다.

### 부동산

첫 화면은 지금 집과 대표 목표 집 하나, 부족한 자금과 계획 시점이다. 관심 후보의 시세·뉴스·세부 비교는 상세로 이동한다. 전체 대출을 해당 집의 대출이라고 표시하지 않는다. 현재 `App.tsx`의 갈아타기 안내 모달은 전체 부채를 “주택 대출”로 부르는 부분이 있으므로 실제 연결 전에 수정해야 한다.

집을 한 번 등록하고 연결된 대출과 지분을 관리한다. 현금 주머니 전액을 이사 자금으로 자동 투입하지 말고 비상금·다른 목표를 제외해 사용 가능 자금을 확인한다. 목표 집을 바꾸면 이전 가정과 달라진 항목을 보여준다. 실제 기능에서는 선택과 계획이 재접속 후에도 유지되어야 한다.

## 5. 부부 앱으로서 필요한 차이

- 각자 소유는 유지하되, 홈의 대표 목표는 가구 기준임을 명시한다. 부부 전체/개인 전환이 소유권을 바꾸지 않는다.
- 배우자 자료가 없다는 사실과 잔액이 0이라는 사실을 구분한다.
- 큰 변경은 “무엇을, 누가, 언제 바꿨는지”와 이전 값을 확인할 수 있게 한다. 재무 결정의 이유도 함께 남긴다.
- 공유·로그인이 생기기 전의 “한 컴퓨터에서 부부 정보 관리”와 실제 계정 간 공유를 같은 기능처럼 표시하지 않는다.
- 양쪽이 같은 집·같은 계좌를 각각 등록했을 때 중복 가능성을 앱이 알려준다.

## 6. 다음에 구현할 작은 단위

첫 단계는 입력과 첫 결과를 연결한다: 단순한 시작 → 유형별 입력 → 자료 확인 → 저장 → 홈 반영 → 재접속 유지. 캡처/시세 자동화는 이 흐름의 입력 방법으로 붙인다.

다음은 한 번 등록한 종목의 수량·평단가와 시세를 연결한다. 홈·주식·연금에서 같은 원본을 조회하고, 조회 실패/이전 가격 상태까지 포함한다. 뉴스 상세와 실제 연금·부동산 계산은 그 뒤 해당 흐름에 연결한다.

디자인은 현재 톤을 유지하되 실제 사용의 첫 화면을 짧게 만든다. 원장·설명·예시·미래 기능을 모두 첫 화면에 쌓지 않는다. 주식·부동산 메뉴를 없애자는 제안은 아니다.

## 7. 실제로 쉬운지 확인하는 방법

사용성 확인 전에는 개선 효과를 단정하지 않는다. 먼저 만든 사람의 설명 없이 아래 과제를 수행해 보는 소규모 검증을 한다.

| 과제 | 볼 것 |
|---|---|
| 연금 하나를 등록하고 현재 합계를 설명하기 | 입력 시간, 도움 요청, 용어 오해, 중복 등록 |
| 주식의 매입금액·현재금액·손익을 구분하기 | 기준 시각/통화 이해, 조회 실패를 0원으로 오해하는지 |
| 본인/배우자/부부 전체로 전환하기 | 소유자와 가구 목표를 혼동하는지 |
| 집과 대출을 넣고 순자산 설명하기 | 지분 중복·전체 부채의 잘못된 연결 |
| 뉴스에서 사실과 해석을 구분하기 | 출처·시각·불확실성을 찾을 수 있는지 |
| 다음 달 바뀐 잔고만 갱신하기 | 처음부터 재입력하는지, 기존 결정/수량을 보존하는지 |

첫 자산 등록 3분, 월 갱신 5분 이내를 초기 목표로 제안한다. 5분 갱신은 기존 PRD 지표이며, 3분 첫 등록은 검증 전 제안이다. 성공 시간뿐 아니라 오류·중복·도움 요청을 함께 기록한다.


## 2026-10-27 UX-01 반영 결과

| 우리 목표 | 각자 은퇴 나이, 부부 월 생활비 | 우선 두 질문, 나이 미입력은 같은 화면에서 보완 |
| 현재 연금 | 국민연금 예상액, 퇴직연금 종류, 등록 적립금 | 국민연금 예상액을 찾는 방법을 입력 옆에서 안내. DB/DC/IRP/모름 선택에 맞는 항목만 표시 |
| 앞으로 납입 | 사람·계좌별 납입 계획 | 기본 표시는 월 납입, 연 납입과 명시적으로 전환. 단위 환산은 코드에서 처리 |
| 계산 가정 | 수익률, 물가, 수령 기간·개시 | 접힌 상세 설정. 현재 적용값·기본값 사용 여부가 보이게 함 |

‘바꿔보기’는 현재 저장한 계획과 분리한다. 가정 수정 → 현재 계획과 나란히 비교 → ‘이 계획으로 저장’으로 연결하고 기존 계획으로 돌아갈 수 있게 한다. 기존 엑셀 직접 편집은 유지할 수 있으나 저장 중/저장됨/실패 상태와 되돌리기를 제공한다. 모든 셀마다 확인 모달을 띄우자는 제안은 아니다.

현재 ‘나 / 배우자’ 열 아래에 ‘수익률 / 물가’를 나란히 배치하는 행은 의미가 맞지 않는다. 가구 공통 가정은 별도 영역으로 분리한다. 빈 칸의 기본값도 회색 글씨만으로 구별하지 말고 ‘기본값 적용’이라고 표시한다.

### 리밸런싱: 이번 판단과 실행을 먼저

1. 대상 묶음과 포함 계좌, 현재 적용 전략·운용 방식, 잔고/가격 기준 시각을 상단에 고정한다. 새 사용자는 계좌 연결부터 안내한다.
2. 판정 한 줄: ‘범위 안 / 납입금으로 조정 가능 / 매도·매수 검토 / 확인 필요’. 이유와 근거 수치는 계산 결과에서 가져온다. 데이터 미확정일 때 거래 권유나 정상 판정을 만들지 않는다.
3. ‘이번에 넣을 돈’과 납입 계좌를 함께 고른다. 변경 전후를 같은 잔고·가격 스냅샷으로 비교한다. 주문표를 보거나 기록할 때 다른 가격으로 조용히 재계산하지 않는다.
4. 현재/목표/차이는 자산군별 한 줄에 모으고 계좌별 주문표를 바로 아래에 둔다. 모바일은 계좌 → 매도 → 매수 카드 순서, PC는 표를 사용한다. 미확정 수량은 확정 주문과 구분한다.
5. ‘주문표 확인’과 ‘직접 주문 예정으로 기록’, ‘이번엔 보류’, ‘실제 거래 후 잔고 갱신’을 구분한다. 수락 기록만으로 보유량이나 홈의 완료 상태를 바꾸지 않는다.

세 투자 원칙을 한 번에 보려는 기존 요구는 유지한다. 현재 점검 요약 다음에 세 원칙 비교를 한 화면에서 제공하고, 탭으로 한 전략씩 숨기지 않는다. 비교 결과가 마음에 들어도 저장 전략은 자동으로 바뀌지 않는다. 적용할 때는 대상 묶음과 변경 전후를 보여준다. 상세 교육 설명·예시 종목은 펼쳐볼 수 있게 한다.

‘왜 지금’ 설명은 주문표 옆에서 확인할 수 있게 하되, 먼저 코드가 만든 근거를 표시한다. 대화형 Agent는 ‘이 결과가 나온 이유’·‘지난번 보류 사유’·‘추가 입력 안내’에 연결한다. 대화창이 기본 설정·금액 확인·결정 기록 화면을 대신하지 않게 한다.

### 두 보기와 모바일을 정리하는 방식

엑셀과 카드를 서로 다른 제품처럼 유지하기보다 같은 업무의 ‘요약 보기 / 표로 보기’로 연결한다. 첫 접속 엑셀 기본값은 기존 결정대로 유지할 수 있다. 바뀌어야 할 것은 기본 외형보다 데이터·기능·주소의 일치다. 보기 전환 후에도 사람·계좌·가정·현재 작업 단계가 유지되어야 한다.

모바일에서는 중요한 숫자와 다음 행동을 가로 스크롤 없이 읽게 한다. 표 전체 편집은 명시적으로 진입하는 상세 작업으로 남긴다. 카드형 좌측 하단의 고정 ‘엑셀 보기로’ 버튼은 모바일 하단 홈 탭 위에 겹치므로 상단 보기 메뉴로 옮기는 안을 제안한다. 숫자·입력 라벨은 본문 수준으로 읽히게 하고, 핵심 설명을 작은 회색 각주에만 두지 않는다.

### 구현 순서와 검수 조건 제안

| 단계 | 변경 범위 | 완료를 판단할 과제 |
|---|---|---|
| 1. 연결과 판정 | 두 보기 경로, 미설정/부분 계산 상태, 계좌 등록→묶음 설정, 주문표 계좌 표시 | 새로고침해도 같은 화면. 새 계좌로 등록부터 주문표까지 도달. 계산하지 않은 계좌를 정상으로 표시하지 않음 |
| 2. 홈 | 소개 축소, 계획 요약·할 일 우선, 대상 정보를 갖고 이동 | 처음 10초 안에 현재 범위·다음 행동을 설명할 수 있는지 사용자에게 확인 |
| 3. 연금·은퇴 | 공통 API 연결, 부족 구간 차트, 목표→연금→납입→가정, 계획 비교 | 나이/생활비 변경 전후를 비교하고 원래 계획으로 돌아오기. 같은 입력은 두 보기에서 같은 결과 |
| 4. 리밸런싱 | 판정·납입·계좌별 실행 순서, 비교/적용 분리, 거래 후 갱신 | 사용자가 주문 대상 계좌와 ‘기록만 됨’을 설명하고, 보류 또는 실제 거래 후 갱신까지 마무리 |
| 5. 모바일·복구 | 세로 요약/입력, 저장 상태, 오류 복구, 접근 가능한 버튼 | 390px·360px에서 핵심 결과를 좌우 이동 없이 확인. 저장 실패 후 입력 보존, 키보드 이동·초점 확인 |

시간 목표는 제안이며 달성 측정 전이다. 이번에 확인한 것은 시각 구조·코드의 데이터 연결·합성 데이터의 탐색 동작이다. 실제 사용자의 이해도·완료 시간·세부 계산 정확성·실제 시세/구글 연결은 이번 검토 범위에 포함하지 않았다.

### 설계 참고

중요한 옵션을 먼저 보여주고 드물게 쓰는 상세 설정을 이어서 제공하는 원칙은 [NN/g의 Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)를 참고했다. 여기서는 항상 필요한 판정과 금액은 숨기지 않고 긴 가정·교육 설명에 적용한다.

중요한 변경에 검토·수정·되돌리기 수단을 주는 원칙은 [W3C의 Error Prevention](https://www.w3.org/WAI/WCAG22/Understanding/error-prevention-legal-financial-data.html)을 참고했다. 모든 저장마다 확인을 추가하라는 의미가 아니며, 전략 적용·계획 저장·주문 의사 기록의 차이가 분명해지도록 적용한다. 본 검토는 WCAG 적합성 인증이 아니다.
