# SHARE-03 서버 검증 — 2026-11-07

공통 파일 생성·기존 파일 선택 결과 검증·고정 가구 연결·복원 서버 범위를 완료했다. 운영 가구의 파일 연결과 제품 전체 사용 완료를 뜻하지 않는다. 원래 후속 범위인 초대(SHARE-04), 자료 이전/공유 쓰기(SHARE-05), 생성/선택 UI(SHARE-06), 두 계정 통합 검수(SHARE-07)는 그대로 남는다.

## 이번 실제 Google 검수

저장된 오너의 동의를 사용해 새 검수용 파일 1개만 만들었다. FastAPI TestClient는 실제 인증/공통 파일 HTTP 경로를 호출하고 Google Drive/Sheets 요청은 실제 네트워크로 수행했다. 별도 인증 저장소를 사용했으며 운영 가구에는 테스트 파일을 연결하지 않았다. 실사용 금융 자료는 읽거나 쓰지 않았다.

| 확인 | 결과 |
|---|---|
| 새 파일·필수 탭/머리글 생성 | 통과. 오너 소유·편집 가능 검사를 거친 준비 완료 응답 |
| 순차·동시 생성 재요청 | 통과. 실제 생성 POST 1회, 같은 ID 또는 처리 중 409 |
| 로그아웃 후 로컬 세션 재발급 | 통과. 미인증 401, 새 세션에서 같은 실제 파일 복원 |
| 새 HTTP 클라이언트로 상태 재조회 | 통과. 같은 ID·정상 연결 복원 |
| 이미 앱 접근 승인된 기존 파일 선택 API | 통과. 별도 가구 검수 저장소에서 선택, 원본 내용 유지 |
| 로컬 파일 권한 제거·복원 | 통과. 연결 오류에도 ID 유지, 권한 복원 후 같은 파일 정상 조회 |

검수 후 새 테스트 파일만 휴지통으로 이동했다. 임시 저장소의 권한을 제거하고 임시 인증 DB를 삭제했다. 비밀값 없는 결과와 테스트 파일 확인용 manifest는 Git 제외 `data/local/share03-live/`에만 보관한다. 계정·토큰·파일 ID는 이 문서와 작업 로그에 기록하지 않는다.

## 자동 검수와 이번 확인의 한계

- 직전 서버 수정 실행: 전용 68개 포함 Python 515개 통과. 빈/손상 머리글 거부, 타인 소유·권한 오류·삭제 응답·생성 응답 유실 등 합성 회귀 근거를 유지한다. 이번에는 제품 코드를 추가 수정하지 않았다.
- 이번 주 대화: 인증 브라우저 7개(격리 포트 8783)·웹 빌드 통과. 이 브라우저는 가짜 인증 제공자와 임시 DB를 사용하므로 실제 Google 로그인 검수와 구분한다.
- 실제 Google 계정으로 다시 로그인하는 화면, 타인 계정의 파일, Google 계정 전체 동의 철회는 이번 실검수 범위가 아니다. 로컬 세션 재발급·로컬 파일 권한 삭제를 그런 검수로 표현하지 않는다.
- 임의 기존 파일을 Google Picker에서 새로 승인하는 화면은 아직 구현되지 않은 SHARE-06 범위다. 여기서는 이미 앱에 승인된 실제 파일을 선택 API에 전달해 검증했다. Picker 화면·키 설정 요구사항을 제거하지 않고 SHARE-06 메모와 작업표에 명시했다.

## 후속 화면 설정

Google Picker 브라우저 선택에는 같은 프로젝트의 API 키·프로젝트 번호와 단기 OAuth 토큰이 필요하다. 키의 웹사이트 제한에는 실제 앱 출처와 `https://docs.google.com/*`를, API 제한에는 Google Picker API를 지정한다. 이는 API를 사용으로 설정하는 것과 별도다. [Google 공식 웹 Picker 설정](https://developers.google.com/workspace/drive/picker/guides/web-picker)

SHARE-06 구현 시 설정과 실제 파일 선택·취소/거부·복원 화면을 검수한다. 운영 장부의 이전/공유 쓰기가 준비되기 전에 빈 검수 파일을 운영 가구에 고정하지 않는다.
