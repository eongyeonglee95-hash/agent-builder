# 부동산·갈아타기 탭 참고 리서치 — 아실 · 호갱노노 · 직방 · 디스코 · 갈아타기 앱 외

조사일: 2026-11-07 · 범위: 우리 집+현금으로 상급지로 갈아타는 계획을 돕는 기능(중개·청약·상업용 제외) · 원칙: 글로 확인한 것만 적는다. 앱을 직접 열어 보지 않았고, 근거는 앱스토어 설명·기사·블로그/커뮤니티 글이다. 근거 수준을 표에 함께 적었고, 확인하지 못한 것은 "확인 못 함"으로 적었다.
관련: 컨셉 시안 5종(Design 캔버스, 아래 §5), 현재 코드 `backend/property_move.py`·`backend/property_market.py`·`tools/property_move.py`.

## 한 줄 요약
시장 정보(실거래 겹쳐 보기·매물 증감·신고가·입주 물량·학군)는 아실·호갱노노가 이미 잘한다. 그러나 조사한 서비스 중 **우리 집 평가액·대출·현금·저축을 넣어 "얼마가 더 필요한가"를 보여주는 곳은 없다.** 가장 가까운 '아파트 갈아타기' 앱도 두 집의 실거래 차이만 추적한다. 그러니 시장 기능은 빌려 오고, 계산의 중심을 우리 자금에 두는 것이 차별점이다.

## 2. 가져올 것 — 우선순위

### A. 바로 가능 (지금 데이터: 국토부 매매 실거래 + 부동산뱅크 매물)
1. **실거래 겹쳐 보기 + 차이 선** (아실) — 우리 집과 목표 단지들을 한 그래프에, 그리고 "목표 − 우리 집" 차이 선을 따로. 컨셉 ②의 12개월 격차와 합친다.
2. **차이 추적 + 기준선 알림** (갈아타기 앱 + 그 앱 사용자 요청) — 기준을 실거래 차이가 아니라 **우리 자금으로 계산한 "더 필요한 돈"**으로. 사용자가 정한 금액 아래로 내려오면 알림.
3. **호가 vs 실거래 % 표시** (호갱노노 과대 호가) — 숫자는 보여주되 "적정가/과대" 판정은 붙이지 않는다. `tools/property_move.py:asking_vs_trades`가 이미 계산한다.
4. **신고가·하락 거래 표시** (호갱노노) — 관심 단지의 역대 최고가 거래, 최고가 대비 % 낮은 거래를 월간 리포트 한 줄로.
5. **같은 단지 면적별 비교** (호갱노노) — 59·84·114㎡ 나란히. 컨셉 ① "목표 면적" 레버의 근거.
6. **알림 주기 선택** (호갱노노) — 즉시 / 하루 1번 / 주 1번.

### B. 정기 수집이 먼저 필요
7. **매물 수 증감** (아실·리치고) — 주 1회 저장해서 그린다. 출처가 부동산뱅크 하나라 절대 숫자보다 방향 참고용으로 표시.
8. **매물 한 건씩 이력** (호갱노노 알림보다 한 단계 더) — 매물 번호 기준 처음 본 날·인하 횟수·사라진 날. 다른 서비스는 알림만 주고 이력은 안 보여준다(확인한 범위에서). "사라짐"은 거래가 아니며, 실거래 신고가 들어오면 연결.
9. **전세가율·갭** (아실·호갱노노) — 국토부 전월세 실거래 API 추가 필요. 세 끼고 먼저 사는 순서(컨셉 ⑤) 검토용.

### C. 공공 데이터로 붙일 후보 (출처 조사 먼저 — 확인 못 함)
10. 단지 주변 입주 물량 1~3년 (아실·호갱노노·부동산지인)
11. 학군 (아실·호갱노노) — 학교알리미 등
12. 구 단위 거래량·인구 이동 (호갱노노·부동산지인) — 국토부·통계청
13. 출퇴근 시간 (호갱노노 출구) — 지금 거주 메모 `Living.commute`를 숫자로

### D. 가져오지 않음
| 기능 | 이유 |
|---|---|
| 리치고 미래가격·투자점수, 부동산지인 지인 지수 | 예측·추천 금지 원칙(CLAUDE.md). 공개 오차도 20%대 |
| 과대 호가·저평가 판정 문구 | 판단은 사용자 몫. 숫자와 기준만 |
| 네이버 매물 자동 수집 | 이용약관·차단 |
| AI 중개사(단지 추천), 입주민 후기 커뮤니티, 3D 투어, 청약, 경매 | 갈아타기 결정과 거리가 멀거나 우리가 만들 수 없는 데이터 |
| 디스코 등기 조회 | 범위 밖. 계약 직전 체크리스트에 외부 링크 정도 |

## 3. 우리만의 자리
- 계산의 중심 = **더 필요한 돈** = (목표 집 가격 + 사는 비용) − (우리 집 평가액 − 대출 − 보증금 − 파는 비용 + 현금) − 새 대출. 식은 `tools/property_move.py:move_budget`, 규칙은 `CALCULATION_RULES.md` §6-M.
- 시장 정보는 "더 필요한 돈이 왜 바뀌었나"(우리 집 / 저축 / 목표 집 가격)의 근거로만 쓴다.
- AI 리포트는 코드가 만든 숫자 JSON으로 문장만 쓰고, 문장 속 숫자를 입력과 대조해 맞지 않으면 쓰지 않는다. 전망·추천 표현 금지.

## 4. 데이터 한계
- 실거래 신고 기한이 계약 후 30일이라, 리포트 시점의 직전 달 거래는 덜 잡힌다. 리포트에 항상 표시.
- 호가 출처는 부동산뱅크 하나(`backend/property_market.py`, 최대 10페이지·15분 캐시). 네이버보다 매물이 적다.
- 우리 집 평가액은 등록 시 입력하거나 수동으로 갱신한다. 현금은 갈아타기 계획에 직접 입력한다. 대출 한도(LTV·DSR)는 계산하지 않는다. 월간 리포트가 의미 있으려면 셋 다 정해야 함(미결 — 현금 출처 a/b/c 질문 보류 중).

## 5. 컨셉 시안 (2026-11-07, Design 캔버스 "갈아타기 컨셉 시안", 숫자는 모두 예시)
캔버스: https://claude.ai/artifact/1m3jRzux49qWzA4XVs5uHr (비공개 — 공유 메뉴로 공유해야 다른 사람이 열 수 있음)
1. **사다리** — 관심 단지를 가격순으로 쌓고 우리 자금이 닿는 높이를 수면선으로. 레버(저축·대출·면적)로 수면 이동.
2. **격차 분해** — 더 필요한 돈 변화를 우리 집 / 저축 / 목표 집 가격으로 분해 + 단지별 12개월 격차.
3. **월간 편지** — 한 줄 요약 → 단지별 세 줄 → 우리 메모 → 확인할 것, 숫자마다 출처 번호와 "숫자 대조 통과" 배지.
4. **매물 레이더** — 주간 수집 기반 매물 수·호가 띠·매물별 이력, 우리가 정한 규칙으로만 알림.
5. **갈아타기 순서** — 먼저 팔기 vs 먼저 사기, 월별 손에 있는 돈, 지켜야 할 기한(세금 기한은 출처 확인 전 빈칸), 부부 체크리스트.
제안 조합: ①을 첫 화면, ②·④를 단지 상세, ③을 월간 리포트, ⑤를 목표 단지를 정한 뒤의 화면으로. 결정 전.
