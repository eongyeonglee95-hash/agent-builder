# 부동산 정기 리포트 수집·분석 설계

조사일: 2026-11-09 · 작성: Codex · 상태: 공식 출처 확인 및 설계 완료, 자동 수집·AI·화면 연결 전

사용자 목적: 관심 상급지와 여러 단지의 주간·월간 흐름을 누적하고, KB 등 기관 자료와 이상우 등 전문가 해석을 함께 분석한다. 매수·갈아타기 결정은 사용자가 내린다. 이 문서는 기존 [시안 조사](PRIMARY_SOURCES_AND_CONCEPTS.md)를 보완한다. 아래 화면·분석 방식은 제안이며 사용자 확정으로 기록하지 않는다.

## 1. 수집할 자료와 확인 범위

자료의 발행 주기와 우리 서비스의 점검 주기는 별개다. 주간 자료는 새 호 발행을 확인하고, 월간 자료는 원문 공표일에 맞춰 갱신한다. 정해진 요일을 모든 발행처에 공통 적용하지 않는다.

| 우선순위 | 자료 | 발행 주기 | 얻을 정보 / 연결 목적 | 이번에 확인한 수집 경로와 한계 |
|---|---|---|---|---|
| 1 | KB부동산 주택가격동향 통계 | 주간·월간 | 매매·전세 지수, 매수우위·전세수급, 거래활발·전망 등. 지역 흐름의 기준선 | [데이터허브](https://data.kbland.kr/kbstats/wmh), [공식 이용가이드](https://file.kbland.kr/image/kbstar/land/pdf/datahub_guide_202307.pdf). 지표 목록은 2023.07 가이드 기준. 현재 지표별 파일·공표 지역·이용 조건 재확인 필요 |

KB의 선도아파트50·PIR·면적별 가격 등은 관심 상급지 분석의 확장 후보다. 각 계열의 공표 범위와 표본을 확인한 뒤 추가하며, 모든 지표가 서울 25구 또는 개별 단지까지 제공된다고 가정하지 않는다. 수급·거래활발 지수는 실제 매물 수나 거래 건수와 다른 계열로 저장한다. [KB 공식 가이드](https://file.kbland.kr/image/kbstar/land/pdf/datahub_guide_202307.pdf)

이상우의 [네이버 프리미엄 콘텐츠](https://contents.premium.naver.com/tinycare/realestatemrlee)는 검색상 채널·구독 페이지를 확인했지만 본문 직접 접근은 제한됐다. 월간 종이책과 같은 상품인지, 어떤 자료를 다운로드할 수 있는지, 발행 일정은 확인되지 않았다. 제목만으로 유료 본문을 요약하지 않는다.

## 2. 자동 수집 가능성을 구체화하는 방법

### 통계

한국부동산원은 [공식 Open API](https://www.reb.or.kr/r-one/portal/openapi/openApiIntroPage.do)와 [개발가이드](https://www.reb.or.kr/r-one/portal/openapi/openApiDevPage.do)가 있다. 인증키·통계표 ID·지역 코드·단위를 확인해 수집기를 연결할 수 있다. API의 존재를 확인한 단계이며 실제 인증 호출·특정 계열의 수신은 아직 하지 않았다.

KB 데이터허브는 JavaScript 화면이다. 이번 텍스트 열기는 실행 안내만 반환했고 별도 브라우저 확인은 연결 재설정으로 실패했다. 따라서 현재 파일 다운로드 성공이나 공개 API 제공을 주장하지 않는다. 다음 구현은 공식 제공 파일의 실제 취득과 이용 조건을 먼저 검증하고, 필요하면 사용자가 받은 엑셀을 가져오는 경로부터 지원한다. 비공개 내부 API에 의존하는 설계를 먼저 확정하지 않는다.

### 보고서·전문가 자료

- 출처 URL·제목·저자·발행일·대상 기간·접근 상태부터 목록에 쌓는다.
- 공개 웹 자료는 허용 범위의 근거와 자체 분석을 원문 링크로 연결한다. 원본 파일 저장은 출처별 허용 범위를 따른다.
- KB경영연구소의 [저작권 정책](https://www.kbfg.com/kbresearch/about/policy.do)은 재게재·활용 조건과 파일 직접 업로드 제한을 명시한다. 서비스에서 보고서 원문 전체를 복제·재배포하는 경로는 기본값으로 두지 않는다. 대량 본문 보관·자동 처리 범위는 이 정책을 따로 확인해야 한다.
- 유료 웹 콘텐츠·종이 월간지는 구독한다고 자동으로 수집 권한이나 PDF가 생긴다고 가정하지 않는다. 사용자가 제공한 읽기 메모 또는 처리 가능한 자료를 연결하고, 웹 접근·파일 보관 범위가 확인되면 확장한다.
- 업로드 자료와 개인 메모는 비공개로 보관한다. 읽지 못한 원문은 `본문 미확인`으로 남기고 분석에 쓴 근거에서 제외한다.

즉 공개 목록·발행 정보·공식 통계부터 수집하고, 본문 접근 수준에 따라 분석 깊이를 달리하는 구조다. 서비스가 앞으로 수집할 것과 이번에 수집·확인한 것을 구분해 표시한다.

## 3. 사용자가 매주 다시 열어볼 이유

| 기능 | 사용자가 읽게 될 결과 | 필요한 통제 |
|---|---|---|
| 지난 호와 달라진 내용 | 새로 등장한 지역·이슈, 강화/약화/철회된 주장, 수치 변화 | 같은 저자·같은 시리즈의 문서끼리 비교. 언급이 사라졌다고 견해 철회로 단정하지 않음 |
| 내 관심 구에 연결 | 강남구·서초구·송파구별로 관련 통계와 리포트 근거 표시 | 직접 언급 / 구 수준 배경 / 서울 공통 배경을 구분. 지역 자료를 단지의 직접 근거로 표시하지 않음 |
| 의견과 데이터 대조 | 전문가 주장 옆에 지지하는 관측·상충하는 관측·미확인 자료 | 인과 설명과 단순 동행을 구분. 상관관계만으로 전문가 주장을 확정하지 않음 |
| 기관 간 차이 추적 | KB와 부동산원이 같은 방향인지, 변화 폭의 차이가 지속되는지 | 기간·지역·주택 유형 정렬 후 비교. 다른 지수를 평균내 하나의 정답으로 만들지 않음 |
| 관심 단지의 상대 흐름 | 지역 전체의 변화 중 내 단지는 어떤 가격·거래·호가 변화가 있었는지 | 실거래 표본 수·면적·층·신축/구축 구성 차이와 신고 지연 표시 |
| 가설의 이후 경과 | 작성 당시 주장·조건·기간과 1/3/6개월 뒤 관측을 나란히 확인 | 평가 기간과 지표를 먼저 정함. 검증 시점 전에는 판단 보류; 사후에 유리한 구간만 선택하지 않음 |

자료 수가 아니라 독립적인 근거 수를 센다. 예를 들어 KB 통계를 인용한 뉴스·리포트 세 편은 독립적인 통계 세 개가 아니다. 문서의 발행처와 그 문서가 인용한 원자료를 모두 기록한다.

### 가상의 분석 예시 — 실제 KB·이상우 발언 아님

“선호 지역의 전세 공급이 줄어든다”는 가설이 있다면 다음을 붙인다.

1. 해당 구의 전세 광고 수와 동일 수집 범위 유지 여부.
2. 해당 지역에 공개되는 전세수급·전세가격 계열의 변화.
3. 관심 단지의 전세 실거래 표본, 호가 분포와 변화.
4. 주변 입주 일정·진행 단계와 시점 변경.
5. 반대 근거: 광고 감소가 수집 누락·계약 갱신·월세 전환 때문일 가능성.

AI 결과는 `관측된 사실 → 가능한 해석 → 반대 근거 → 다음 확인 항목`으로 만든다. 데이터가 부족하면 부족한 부분을 답한다. 사용자가 원할 때 특정 주장에 대해 원문과 관측치를 함께 열 수 있어야 한다.

## 4. 화면에 넣는 위치

부동산 기본 탭은 사용자 확정대로 **트래킹 / 갈아타기**를 유지한다. 다음은 트래킹 안의 리포트 구성 제안이며 기본 화면 교체는 하지 않는다.

| 위치 | 내용 |
|---|---|
| 트래킹 상단의 작은 주간 브리핑 | 기간 선택, 새 자료 수, 관심 지역에 변화가 큰 항목 3개, 데이터 기준일 |
| 기존 구별 탐색 | `서울 전체 → 구 → 단지`. 선택한 범위에 관련된 보고서만 필터링 |
| 리포트 목록 | 발행처·발행일·자료 기준월·접근 상태를 한 줄씩. 큰 카드의 반복은 피함 |
| 보고서 상세 | 핵심 주장, 이전 호와의 변화, 관련 차트, 반대 근거, 원문 위치 |
| 단지 상세 | 직접 언급 자료와 지역 공통 배경을 따로 보여주고 실거래·호가 차트에 연결 |
| 주간·월간 저널 | 당시 관측을 고정한 자체 브리핑. 이후 정정은 새 버전과 차이로 남김 |

주간에는 가격·수급의 방향 변화와 관심 구의 새 근거를, 월간에는 공급·거래·금융까지 합쳐 가설의 경과를 보여준다. 새 보고서가 없는 주에는 기존 문서를 새 발행물처럼 재노출하지 않는다.

## 5. 누적 저장과 계산 계약

최소 네 종류의 기록을 분리한다.

| 기록 | 필수 내용 |
|---|---|
| 출처 | 제공기관·저자, 원본 주소, 자료 종류, 발행 주기, 접근/보관 조건, 마지막 성공 확인 |
| 문서 버전 | 제목, 호수, 발행일, 최초 발견일, 확인일, 허용된 원문의 해시/버전, 접근 수준, 페이지·문단 위치 |
| 수치 관측 | 원자료·계열 ID, 지역 코드/공표 수준, 주택 유형, 단위, 관측 기간, 공표일, 최초 수신일, 지수 기준시점, 개정 버전 |
| 주장·근거 | 원문 위치, 사실/해석/전망, 대상 지역·기간·조건, 연결 관측 ID, 지지/상충/미확인, 후속 확인일 |

- 숫자 추출 후 단위·기간·지역을 검증하고 변화율과 상대 지표는 코드로 계산한다. AI는 계산 결과와 인용 가능한 근거를 설명한다.
- 주간 변동률의 월 누적은 유효한 해당 주간을 곱해 산출하며, 별도 조사인 월간 지수와 동일하다고 표시하지 않는다.
- 지수 기준연도 변경·표본 개편을 기록한다. 같은 계열인지 확인되지 않으면 선을 이어 붙이지 않는다.
- 최근 거래량은 신고 지연 때문에 잠정값으로 취급하고 정정·해제 이력을 반영한다. 전월 확정치와 이번 달 일부 신고치를 곧바로 비교하지 않는다.
- 백테스트는 그 시점에 공표·수신된 자료만 사용한다. 나중에 수정된 전체 시계열로 과거 리포트의 판단을 덮어쓰지 않는다.
- 매물 광고 수·실거래 건수·중개업소 설문지수를 별도 보관한다. 광고 소멸을 거래 성사로 계산하지 않는다.
- 수집 실패는 값 0과 구분한다. 자료가 없는 구에 서울 값을 구별 값처럼 복제하지 않는다.

## 6. 실제 자료로 확인한 설계 사례

KB주택시장 리뷰 **2026년 10월호는 10월 15일 발행**됐지만, 공개 요약에는 **9월 가격과 8월 거래**가 함께 들어 있다. 따라서 문서에 `10월` 태그 하나만 달면 관측 시점이 섞인다. 보고서 호수와 각각의 지표 기준 기간을 따로 저장해야 한다. [발행 페이지](https://www.kbfg.com/kbresearch/report/reportView.do?reportId=2001362), [웹 요약](https://kbthink.com/realestate/insights/research/261015-1.html)

이것이 수집 검증용 실제 사례이며 현재 시장 전체에 대한 투자 판단은 아니다. KB 공개 요약을 읽어 기간 혼재를 확인했으며, PDF 본문 전체나 유료 전문가 보고서를 읽었다고 주장하지 않는다.

## 7. 구현 순서와 완료 기준

1. **출처함과 수동 가져오기:** 위 우선순위 1 자료의 발행 정보·원문 링크, 사용자가 이용 가능한 파일/메모, 지역 태그. 새 호·정정 호·접근 실패 상태를 구별한다.
2. **공식 통계 연결:** 부동산원 API의 실제 계열 수신, KB 제공 파일의 취득·이용 범위 검증 후 파서 연결. 원표와 표본 수치 대조, 단위·지역·날짜 검증을 통과해야 완료다.
3. **변화 분석과 근거 연결:** 이전 호 대비 주장 변화, 동일 출처 중복 제거, 관심 구→단지 연결, 반대 근거. 모든 숫자·주장이 원문 위치 또는 관측 기록으로 돌아가야 한다.
4. **정기 브리핑:** 발행 감지 → 검증 → 주간/월간 초안 → 수정 이력. 월간 자료는 발행 지연을 허용하며 당시 정보로 만든 보고서를 보존한다.
5. **연구 지표 검증:** 상대 강도·전세 압력 등 가설을 사전에 정의하고 충분한 이력에서 검증한다. 검증 전 임의 종합 점수·매수 신호를 내지 않는다.

현재 구현된 수집기·스케줄·알림·AI 호출은 없다. 이번 산출물은 원출처 조사, 확인된 발행 사례와 접근 제한 기록, 기존 화면에 연결할 설계다. 공개 통계부터 진행 가능하며 유료 자료는 사용자의 실제 구독/보유 형식과 해당 이용 조건에 따라 연결한다.
