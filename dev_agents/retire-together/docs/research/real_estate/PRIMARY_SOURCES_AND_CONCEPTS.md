# 관심 부동산 정량 리서치의 공식 근거와 화면 컨셉

조사일: 2026-11-07 · 작성: Codex · 상태: 최신 구현·구별 구조/UI 재구성은 §11~12. §4·§10은 초기 컨셉 설계와 구현 기록

관련: Claude의 [부동산 앱 비교 리서치](APPS_REFERENCE.md), [제품 맥락](../../MASTER_CONTEXT.md), [계산 규칙](../../CALCULATION_RULES.md). 기존 리서치를 보존하고 공식 자료에서 확인한 내용, 추가 확인이 필요한 주장, 네 가지 화면 컨셉의 구현 조건을 보완한다.

사용자의 우선 목적은 **여러 관심 부동산을 주간·월간으로 추적하고, 가격·거래·매물·공개 자료를 깊이 분석하는 개인 부동산 리서치 서비스**다. 주식의 정량 리서치처럼 지표의 정의와 비교 조건을 고정하고, 시계열·상대가격·분포·사건의 근거를 축적해 사용자가 가격을 판단할 수 있게 한다. 공개돼 있지만 흩어져 있거나 연결해 읽기 어려운 정보의 변화와 모순을 찾아내는 것이 핵심이다. 비공개 정보나 특별한 접근권한을 갖는다는 뜻은 아니다.

먼저 관심 단지의 연구를 충분히 하고, **사용자가 가격을 검토할 후보를 선택한 뒤** 세금·자금 조달·매도·매수 순서를 상세 검토한다. 초기 문서의 재원·부족금 중심 화면 방향은 이 사용자 정정으로 대체한다. 투자 적합성 점수, 매수 추천, 진입 시점 판정은 만들지 않는다. 관측 사실·계산 결과·연구 가설·사용자 판단을 분리한다.

## 1. 확인 수준과 조사 범위

| 표시 | 확인한 것 | 확인하지 않은 것 |
|---|---|---|
| 공식 안내 | 운영사 도움말·개발자 앱 설명·공식 발표의 기능 설명 | 해당 계정에서 기능을 직접 실행한 결과, 모든 지역의 제공 범위 |
| 공개 화면 | 공개 웹 HTML의 메뉴·입력·표 구조 | 로그인·유료 단계의 완료 흐름, 데이터의 전수성·정확성 |
| 과거 가이드 | 작성 시점이 명시된 공식 사용 설명서 | 현재 동일한 메뉴·요금·화면의 유지 여부 |
| 설계 제안 | 위 근거를 바탕으로 우리 목적에 맞게 바꾼 흐름 | 경쟁 서비스가 같은 기능을 제공하지 않는다는 주장 |

호갱노노 본 사이트와 직방 메인 웹은 조사 도구에서 403을 반환했다. 호갱노노는 공식 개발자 설명·중개사 안내·운영사 발표로, 직방은 공식 설명·발표와 접근 가능한 세대 페이지로 보완했다. 아실·디스코의 공개 화면, 네이버 도움말, KB 개발자 설명은 열람했다. 앱 로그인·푸시 수신·중개사 상담·유료 기능은 실행하지 않았다.

아래 40개 항목은 기능의 존재 또는 안내 범위를 기록한 것이다. 그 서비스의 데이터를 우리 제품에서 수집할 권한이나 공개 API의 존재를 뜻하지 않는다.

## 4. 연구 중심의 네 가지 컨셉

사용자가 제공한 Google Sheet 캡처는 이미 쓰고 있는 추적 방식의 기준이다. 화면에서 확인한 구조는 다음과 같다. 전체 시트 내용이나 수식·연결 데이터는 확인하지 않았으며, 캡처의 실제 금액·스프레드시트 ID·비공개 이미지를 이 문서에 저장하지 않는다.

- 여러 단지·평형 변형이 열로 나란히 놓인다.
- 고정 정보 행은 지역·단지·평형·연식·세대수·구조, 변화 행은 매가변동·전세가변동이다.
- `23.07.01`, `23.06.01` 등 월별 블록마다 매매가·평당가·전세가·전세가율·매전갭을 기록한다. 이 날짜는 화면 구조를 설명하는 예이며 실제 가격 관측일·발행일의 의미는 추가 확인 대상이다.
- `30평형`, `전화임장(전주)`, `매물임장리스트`, `전화임장` 탭이 보인다. 가격 추적과 현장·전화 확인이 함께 있는 구조다.

새 서비스는 이 **단지 간 비교 × 월별 이력 × 현장 근거**를 확장한다. 표의 친숙함을 유지하면서 각 셀에 출처·확인일·가격 종류를 연결하고, 시계열과 공개 문서 분석을 이어 붙인다. 캡처만으로 매매가·전세가가 실거래·호가·중개사 의견 중 무엇인지 단정하지 않으며 입력 시 가격 기준을 정하도록 한다.

네 컨셉은 같은 가상 관심 목록·기간·관측 자료를 공유한다. 첫 화면의 주요 숫자는 가격·거래·매물·비교 지표와 자료 상태다. 합성 자료임을 분명히 표시하며, 시안의 예시 보고서를 실제 모델·실시간 분석 결과로 표현하지 않는다.

| 컨셉 | 화면의 중심 질문 | 화면 구조 | 아티팩트에서 검토할 핵심 조작 |
|---|---|---|---|
| 퀀트 워크북 | 관심 단지 중 무엇이 달라졌고 어떤 차이를 더 연구할까? | 단지·평형을 열에, 기본정보·지표·월별 블록을 행에 둔 표와 현장 기록 | 고정 정보·월 블록 탐색; 비교 열 선택; 셀 → 원표·원문·임장 메모; 기준일 전환 |
| 상대가치 랩 | 이 단지의 가격과 거래 구조는 비교군에 비해 어떻게 달라졌나? | 거래 점과 시계열, 비교군 상대가격, 호가·실거래 분포, 조건별 원표 | 기간·층 구간 변경; 비교군 전환; 분포 구간 → 해당 거래; 관측 당시/현재 재집계 전환 |
| 정보 레이더 | 가격 밖의 공개 사실에서 놓친 변화·모순·후속 확인은 무엇인가? | 공고·사업 단계·예산·공급 수정의 사건 시간표, 근거 연결망, 연구 가설 노트 | 원문 버전 차이; 사건→관련 단지; 가설→지지·반대 근거; 전화·현장 확인 과제 저장 |
| 주간·월간 저널 | 이번 기간에 무엇이 바뀌었고 무엇을 아직 모르는가? | 기간별 발행본, 전체 관찰 요약, 단지별 변화·반증·자료 공백·질문 | 주간/월간 선택; 문장→셀·원표·원문; 이전 가설 후속; 발행본과 정정 기록 비교 |

### 퀀트 워크북

캡처처럼 관심 단지·평형을 열에 놓고 기본 정보 아래에 월별 매매·전세·비율·차이를 쌓는다. 기본정보와 단지 머리글을 고정하고 월 블록을 접어 탐색한다. 거래 건수·가격 분포·비교군 차이·출처별 광고 수를 추가 지표 행으로 선택할 수 있다. 별도의 단지×지표 요약 보기는 같은 자료를 전치해 정렬하는 보조 화면으로 둔다. 모든 셀은 값과 함께 기간·표본 수·관측 상태를 갖는다.

셀을 열면 계산 정의·가격 기준·출처·지난 값과 관련 전화·임장 메모가 보인다. 현장 기록은 작성일·확인 대상·질문·답변·자료 제공자를 구분하고 해당 월의 관측값에 연결한다. 색은 변화 방향 또는 자료 상태를 표시하며 좋은 투자의 판정에 쓰지 않는다. 지표로 정렬하더라도 임의 가중 투자 점수나 적합도 순위를 만들지 않는다. 비교군·면적 조건 변경과 이전 연구 설정을 보존한다.

### 상대가치 랩

동일 면적·타입을 기본 단위로 거래 점을 먼저 보여주고, 중간값·분위수·거래 건수·조회 기간을 겹쳐 본다. 층별 구간을 바꾸면 표본 구성이 어떻게 달라지는지 같이 보여준다. 가격이 변했는지, 거래된 집의 구성이 달라졌는지 구분할 근거를 제공하되 품질 차이를 자동으로 보정했다고 주장하지 않는다.

선택한 비교 단지와의 금액 차이·비율 차이, 그 차이의 과거 분포를 분석한다. 여기서 상대가치는 관측된 상대가격 연구를 뜻하며 적정 가치나 매수 시점의 자동 판정이 아니다. 현재 호가 분포와 과거 체결가격 분포는 서로 다른 시점·조건이라는 표시를 유지한다. 분포의 일부를 선택하면 해당 광고·거래가 원표에서 강조된다. 거래가 없는 달은 공백으로 두며 직전 거래를 현재 체결가격처럼 연장하지 않는다. 사용자가 충분히 연구한 뒤 후보를 선택하면 별도의 세금·자금 검토로 이동할 수 있다.

### 정보 레이더

공개 정보를 많이 모으는 것보다 **같은 사업·단지와 관련된 문서를 연결하고 변경을 찾아내는 것**에 집중한다. 예를 들어 추진 단계의 발표, 예산의 편성·집행 구분, 입주 예정 시점의 수정, 공급 세대수의 범위 변경을 각각 원문 근거와 함께 기록한다. 발표가 곧 착공·완공인 것으로, 예산 편성이 곧 집행인 것으로 묶지 않는다. 예산·교통·인허가의 구체 출처와 이용 조건은 연결 전 별도 검증 대상이다.

근거 연결망은 단지·사업·문서·사건을 연결하되 관계를 소재지 일치, 사업구역 포함, 일정 변경, 같은 문서의 재인용처럼 구체적으로 표시한다. 기사 여러 개가 하나의 발표를 인용하면 독립 근거 여러 건으로 세지 않는다. AI는 관련성 후보와 요약을 만들고, 직접 확인되지 않은 단지 영향은 가설로 남긴다. 특별한 비공개 정보나 향후 가격 상승의 근거를 확보했다는 표현은 사용하지 않는다.

### 주간·월간 저널

주간에는 새로 관측한 거래·광고 변경·공고·자료 정정을, 월간에는 일정한 비교 조건에서의 가격 분포·거래 구성·상대가격 변화와 연구 질문의 경과를 정리한다. 첫 장은 관심 목록의 달라진 사실, 단지별 상세는 관측 → 가능한 설명 → 반대 근거 → 자료 공백 → 다음 질문의 순서다. 변화가 없거나 자료가 부족한 단지도 빠뜨리지 않는다.

각 수치는 코드 결과, 각 사실은 근거, 해석은 가설이라는 연결을 유지한다. 가격의 적정 여부와 실행 결정은 사용자가 기록한다. 리포트 발행 뒤 늦게 들어온 거래나 해제는 별도 정정으로 남기고 당시 보고서를 덮어쓰지 않는다. 장기적으로 남는 것은 보고서 파일만이 아니라 어떤 질문을 어떤 자료로 검토했고 무엇이 달라졌는지에 대한 연구 기록이다.

### 후보 선택 후의 보조 검토

사용자가 관심 단지를 가격 검토 대상으로 선택한 뒤에만 매수 가정·세금·대출·보유집 매도·잔금일·이사비용을 깊이 검토한다. 이는 연구 화면의 기본 축이나 매수 신호가 아니다. 연금·남겨둘 생활비·소유 지분을 구분하고, 최종 자금과 잔금 사이의 현금 부족을 따로 계산한다. 대출 승인·확정 세액·최적 매수 시점을 자동으로 선언하지 않는다.

## 5. 분석 지표 사전 초안

아래는 구현할 지표의 정의 제안이다. 통용되는 이름만으로 계산을 정하지 않고, 조회 범위·분모·관측 시점·분위수 방식·최소 표본을 규칙으로 고정한 뒤 표시한다. `t`는 연구 기준시점, `W`는 그 시점까지의 사전에 정한 과거 관측 구간이다. 같은 이름의 지표라도 조건이 바뀌면 새 버전으로 취급한다.

| 지표·통제 항목 | 정의·표시할 내용 | 데이터 한계와 해석 조건 |
|---|---|---|
| 추적 단위 | 단지 ID+전용면적+확인 가능한 타입; 비교 면적과 허용 범위 명시 | 공급평형과 전용면적을 혼동하지 않음. 면적을 넓혀 표본을 채웠다면 별도 비교 조건 |
| 층·품질 구성 | 층 구간별 건수, 타입·동·향·수리·입주 조건의 확인 여부 | 공개되지 않은 품질을 추정해 채우거나 층 프리미엄을 자동 차감하지 않음. 보정 모델은 검증 전 미지원 |
| 체결가격 수준 | W 내 유효 거래의 중간값·하위/상위 분위수·범위와 n | 대표 시세나 평가가격이 아닌 관측 거래 요약. 1건이면 분포 요약 대신 거래 1건 표시 |
| 체결가격 변화 | 같은 조건의 두 구간 중간값 차이·차이 비율 | 두 구간 표본 수·층 구성을 함께 표시. 동일 주택의 수익률로 해석하지 않음 |
| 면적당 가격 | 금액 ÷ 명시한 면적; 원/㎡ 또는 원/평의 단위와 전용/공급 기준 고정 | 서로 다른 면적 기준의 평당가를 한 열에서 비교하지 않음. 면적으로 나눠도 품질 차이가 제거되지는 않음 |
| 거래 건수 | W 내 조건에 맞는 유효 신고 건수; 해제·정정·직거래 처리 기준 표시 | 최근 구간은 신고 진행 중. 화면에 잘린 30/60행으로 전체 건수를 계산하지 않음 |
| 거래 회전율 | 기간 내 거래 건수 ÷ 같은 범위의 세대수 | 전체 단지 세대수인지 해당 면적 세대수인지 명시. 대응 분모가 없으면 계산 보류. 같은 집 재거래를 포함할 수 있어 팔린 집의 비중과 다름 |
| 가격 분산 | 예: (75분위 가격−25분위 가격) ÷ 중간값; 원 단위 구간도 병기 | 분위수 계산법·최소표본 규칙 고정. 층·타입 혼합에 따른 분산을 시장 변동성으로 단정하지 않음 |
| 호가와 체결가격 차이 | 같은 면적의 관측 호가 중간값−W 내 실거래 중간값; 비율은 실거래 중간값을 분모로 | 광고/거래 표본 수·서로 다른 기준일·조건 표시. 적정·과대·협상 가능액 판정으로 바꾸지 않음 |
| 출처별 광고 재고 | 기준시점에 해당 출처에서 관측한 유효 광고 ID 수 | 시장 전체 매물이나 집의 수와 다름. 부분 조회는 완전 조회와 직접 증감 비교하지 않음 |
| 광고 유입·이탈 | 같은 출처·조건의 연속된 완전 관측에서 새로 보인 ID와 더 이상 보이지 않는 ID | 이탈은 판매가 아님. 수집 실패 구간은 이탈 처리하지 않으며 재게재·ID 변경을 분리 |
| 동일 광고의 호가 변화 | 지속 식별한 광고 ID의 가격 변경 횟수·변경액·관측 간격 | 최초 관측일이 최초 등록일은 아님. 다른 광고로 바뀌면 동일 집으로 자동 연결하지 않음 |
| 비교군과의 상대가격 | 후보의 동일 조건 가격 요약과 사전 선택 비교군의 차이 또는 비율 | 비교군·가중치·기간을 기록. 입지·품질 차이를 제거한 공정가치 차이가 아님 |
| 상대가격 차이 백분위 | t 이전에 관측한 같은 정의의 차이 분포에서 현재 값의 위치; 동률 처리와 관측 수 명시 | 적정가·상승 확률·매수 신호가 아님. 겹치는 이동구간의 관측은 독립 표본이 아님. 짧거나 결측 많은 이력에는 계산 보류 |
| 전세가율 | 같은 단지·면적·기간의 전세 보증금 중간값 ÷ 매매가격 중간값 | 신규/갱신·계약 유형·표본 수 구분. 월세를 임의 환산해 섞지 않음. 전월세 원천 추가 확인 필요 |
| 매전갭 | 같은 단지·면적·기간·가격 기준의 매매가격 요약−전세 보증금 요약 | 시트의 매전갭과 갈아타기 부족금은 다른 값. 호가끼리인지 실거래끼리인지 표시하고 거래비용·보증금 반환 부담을 포함한 필요자금으로 해석하지 않음 |
| 기간 내 최고가 대비 차이 | 가격 요약 또는 개별 거래와 명시한 조회기간 최고 거래의 차이 | 전체 이력 없이는 역대 최고가로 부르지 않음. 최고 거래의 층·면적·날짜 표시 |
| 공급·사업 변경 | 동일 사업의 이전/현재 단계·세대수·예정일·예산 항목 차이 | 확정과 예정, 편성과 집행, 전체 사업과 일부 구역 구분. 가격 영향의 크기를 자동 산정하지 않음 |

주택가격 비교에서 품질·거래 구성 차이는 별도의 방법론 문제다. Eurostat도 시점 간 품질 조정을 주요 과제로 다룬다. 우리 초기 설계는 조건별 원표와 구성 차이를 노출하는 단계이며 검증된 품질 조정 가격지수라고 표현하지 않는다. [Eurostat 주택가격 방법론](https://ec.europa.eu/eurostat/cache/metadata/en/tipsho20_esms.htm)

상대가격 백분위는 구현 시 예를 들어 `100 × (현재보다 작은 과거 관측 수 + 0.5 × 같은 값의 관측 수) / 과거 관측 수`로 정의할 수 있다. 이 식을 채택하면 과거 구간에 현재 관측을 포함하지 않고, 단위·비교군·기준시점·관측 간격을 고정한다. 이는 제안된 기술 규칙이며 아직 제품에 적용된 계산 계약이 아니다.

모든 지표에 원자료 수·기간·출처·조건·관측 상태를 붙인다. `0`은 완전한 조회에서 해당 값이 실제로 0인 경우, `관측 없음`은 조건에 맞는 기록이 없는 경우, `자료 없음`·`조회 실패`·`부분 조회`·`분모 미확인`은 계산할 수 없는 경우다. 빈칸을 0으로 채워 정렬하거나 색칠하지 않는다.

## 6. 당시 관측 자료와 현재 재집계를 구분하는 데이터 설계

### 시점 네 가지를 분리한다

| 시각 | 의미 | 연구에서의 사용 |
|---|---|---|
| 사건 시각 | 계약일·공고 대상일·예산 의결일 등 사건이 일어난 때 | 달력·거래기간 집계 |
| 원천 공개 시각 | 출처가 자료를 공개한 때, 확인되는 경우만 | 외부에서 알 수 있게 된 시점의 근거 |
| 최초 관측·수집 시각 | 우리 시스템이 해당 버전을 처음 확보한 때 | 당시 연구에 실제로 사용할 수 있었던 정보의 경계 |
| 리포트 기준·발행 시각 | 포함할 자료를 마감한 때와 보고서를 발행한 때 | 동일 입력으로 발행본 재현 |

계약월과 정보가 공개된 달은 다를 수 있고, 신고 내용은 이후 바뀔 수 있다. 계약일만 보고 그 시점의 과거 리포트에 거래를 소급 삽입하면 당시 알 수 없었던 정보를 사용하게 된다. [국토부 자료 이용 안내](https://rt.molit.go.kr/pt/xls/xls.do)

연구 화면은 **당시 관측 자료로 재현**과 **현재까지 반영된 자료로 재집계**를 구분한다. 전자는 기준시점 이전에 관측한 원자료 버전·비교군·규칙만 사용한다. 후자는 해제·정정·늦은 신고를 반영한 새 분석이며 이전 리포트의 결과로 위장하지 않는다. 원천 공개일을 알 수 없으면 최초 관측일을 보수적으로 사용하고, 과거 수집 기록이 없는 기간은 당시 상태 재현 불가로 표시한다.

정량 연구의 미래 정보 참조 편향은 나중에 알게 된 데이터를 과거에 알고 있었다고 취급할 때 생긴다. QuantConnect의 시점별 자료 원칙을 부동산의 늦은 신고·문서 수정·비교군 변경에 적용한 설계다. 전체 기간을 본 뒤 고른 비교군이나 조건을 과거 연구에 몰래 적용하지 않는다. [QuantConnect 연구 가이드](https://www.quantconnect.com/docs/v2/writing-algorithms/key-concepts/research-guide)

현재 공개 호가 구현은 출처 한 곳에서 최대 10페이지를 읽고 15분 캐시를 사용한다. 광고 ID 중복 제거는 여러 중개업소가 같은 집을 올린 경우를 모두 식별한다는 뜻이 아니다. 완전 관측끼리만 증감을 비교하고, 출처 추가·페이지 실패·조건 변경은 수집 범위 변화로 남긴다. [현재 공개 호가 코드](../../../backend/property_market.py)

### 원자료와 연구 결과의 최소 기록

- **연구 대상:** 단지·면적·타입, 관심 등록·해제일, 비교군·가중치·조건 버전. 나중에 제외한 단지도 과거 연구 목록에는 남긴다.
- **원자료 버전:** 출처·원문·가격/문서 종류·사건일·공개일·최초 관측일·수집일·원문 해시·정정/해제·부분 조회 상태. 공개일 미확인은 빈값으로 보존한다.
- **광고 식별:** 출처 내부 광고 ID를 기본키로 유지하고, 같은 집으로 의심되는 광고 묶음은 별도 추정 관계로 기록한다. 확인 전 집 개수로 합산하지 않는다.

- **연구 가설:** 최초 작성 시각·질문·예상 관측·지지/반대 근거·확인하지 못한 변수·후속 검토일·상태 변경 이력.
- **리포트:** 주간/월간 대상 기간·자료 마감·발행 시각·지표와 근거 ID·문장별 연결·정정·사용자 메모. 발행 후 원본은 유지한다.

화면에서 보이는 데이터, 기술적으로 요청 가능한 URL, 허용된 자동 수집, 우리 제품의 재배포는 각각 다른 확인 항목이다. 이번 조사로 민간 서비스의 일반 외부 개발자용 매물 API 이용권을 확보한 것은 아니다. 직방의 특정 제휴 MCP 발표도 우리 앱에 같은 권한을 부여하지 않는다.

## 7. 깊이 있는 공개 정보 연구와 추적 가능한 설명

연구의 깊이는 기사 개수나 요약 길이보다 원문 사이의 관계를 검토하는 데서 나온다. 아래는 특정 단지에 관한 사실 주장이 아닌 조사 작업의 설계다.

| 연구 질문의 형태 | 함께 확인할 공개 근거 | 반대 근거·자료 공백을 남기는 방식 |
|---|---|---|
| 발표된 사업의 단계가 실제로 진전됐는가? | 같은 사업 ID의 이전·현재 공식 단계, 고시, 심의 결과 | 단계 명칭만 바뀐 경우, 조건부 결정, 후속 문서 미확인 |
| 예산 관련 발표의 범위가 바뀌었는가? | 예산안·확정 예산·집행 자료의 항목·회계연도·대상 구역 | 편성액을 집행액으로 비교하지 않음; 우리 단지와의 관계 미확인 |
| 주변 공급 일정이 달라졌는가? | 모집공고·변경 공고·입주 예정자료의 사업·세대수·날짜 | 전체와 일부 구역 구분, 지연 추정과 공식 수정 구분 |

| 호가 변화와 거래 변화가 함께 관측되는가? | 같은 출처의 광고 버전과 당시 확인 가능했던 거래 | 출처 누락·재게재·광고 중복·신고 지연에 대한 대안 설명 |

연구 기록은 `질문 → 관측 지표 → 원자료·문서 → 지지 근거 / 반대 근거 → 남은 공백 → 다음 확인`으로 연결한다. 각 연결에는 관련 단지·사업·날짜·관계의 확인 수준을 남긴다. 문서 인용 횟수를 신뢰 점수로 바꾸지 않으며, 원문을 읽지 않은 요약을 확인된 사실로 승격하지 않는다.

AI의 역할은 서로 다른 자료를 연결할 후보를 찾고, 계산 결과를 설명하며, 빠진 확인 질문을 제안하는 것이다. 가격을 움직인 원인이라고 단정하려면 별도 분석이 필요하므로 사건과 가격의 동시 변화는 우선 관측된 연관으로 쓴다. 가설 상태는 검토 중·근거 추가·반대 근거 발견·보류 등으로 관리하고, 좋은 결과만 남기기 위해 이전 가설을 지우지 않는다.

## 9. 이후 설계에서 유지할 기준

1. 관심 단지는 여러 곳을 동등하게 연구한다. 하나의 대표 목표나 당장 살 후보를 강제로 고르지 않는다.
2. 주간·월간 추적과 깊이 있는 공개 자료 분석이 주 경험이며, 가족 자금과 세금은 사용자의 후보 선택 이후에 다룬다.
3. 같은 면적·기간·비교군의 정의, 표본 구성, 관측 당시의 정보 범위를 먼저 고정한다.
4. 단지·개별 거래·광고·문서·연구 가설을 별개로 관리한다. 광고 소실과 거래 성립을 동일시하지 않는다.
5. 관측 사실·코드 계산·연구 가설·사용자 가격 판단을 구분한다. 적합도·투자 점수·진입 시점 판정은 만들지 않는다.
6. 깊은 연구는 공개 원문의 연결·변경·반증에서 만든다. 특별한 비공개 접근을 암시하지 않는다.
7. 기존 공식 기능 40개와 출처는 보존하며 세부 구조·지표 계약은 독립 시안과 구현 검토 후 정한다.

문서 검수 범위: 공식 기능·출처 보존, 사용자 목적 정정에 맞춘 네 컨셉·로드맵 재작성, 지표·시점·자료 공백·연구 추적 설계 검토. 실제 계정 이용·새 데이터 연동·제품 계산 변경·주간/월간 AI 실행은 수행하지 않았다.

## 11. 사용자 후속 반영 — 서울 흐름과 여러 단지 비교

사용자는 초기 시안을 긍정적으로 평가하고 정보 레이더를 다른 화면에 합치며, 서울 전체 매매·전세 매물이 증가/감소하는지 시각화하고 데이터를 계속 쌓는 방향을 요청했다. 단지 비교는 단일 비교 대상 선택에서 체크한 여러 단지의 동시 비교로 바꾼다.

### 최종 화면 구조

- **시장·관심 단지:** 서울 매물 흐름 / 관심 단지 워크북을 내부 탭으로 전환한다. 서울 전체 광고 수와 25개 자치구의 증감, 증가/감소 구 수, 일별 추이와 상·하위 구를 보고 구 선택 → 해당 구 관심 단지로 이어진다. 타일은 동일 크기·가나다순이며 실제 지도 경계가 아니다.
- **여러 단지 비교:** 워크북과 공유하는 체크 목록, 선택한 0~6개 단지 차트·비교표. 매매/전세/전세가율/매전갭/공급 평당가, 시작월 100·원래 값·각 월의 기준 단지 100을 전환한다. 기준 단지를 해제하면 남은 첫 단지로 바꾸고 선택 해제 상태는 빈 화면 안내로 표시한다. 개별 상세의 거래·광고·전화임장·공공 근거·반증·질문을 연결한다.
- **주간·월간 저널:** 서울의 관측 흐름과 관심 단지 기록을 함께 읽는다. 기존 정보 레이더는 독립 메뉴에서 제거하고 단지 상세와 리포트에서 근거 노트로 연다. 과거 발행본/최신 반영, 메모·질문·텍스트 내려받기는 유지한다.

### 서울 매물 자료를 계속 축적하는 계약

아실 공식 메뉴에서 매물증감·여러단지비교의 존재를 재확인했다. 공개 메뉴는 자동 수집 API나 저장·재배포 이용권의 근거가 아니다. [아실 공식 메뉴](https://asil.kr/app/app_main_pc.jsp)

수집 단위는 `출처 × 주택유형 × 지역 × 거래유형 × 관측시각`이다. 광고 ID·가격·조건·활성 상태와 수집 범위/성공 여부를 보존하고 스냅샷을 덮어쓰지 않는다. 매매와 전세는 별도 계열로, 아파트와 다른 주택 유형도 분리한다. 출처가 다르면 같은 주택의 중복 광고를 확인하지 않은 채 합산하지 않는다.

서울 합계는 같은 기준시점의 25개 구 광고 수를 합산한다. 증감률은 `100 × (현재 합계 / 비교일 합계 − 1)`이며 구별 증감률의 평균이 아니다. 한 구라도 누락되면 서울 합계와 그 값을 사용하는 비교를 보류한다. 시작일 값이 누락되면 시작일 100 환산도 보류한다. 광고 수는 집의 수·거래 건수와 다르며 소실은 판매로 확정하지 않는다.

실제 구현에서는 출처 확인 후 일별 관측을 제안한다. 중복 실행 방지, 출처별 호출 조건, 부분 실패/재시도, 나중에 확보한 과거 자료의 관측일, 원본/수정 버전을 보존한다. 주간·월간 리포트는 마감 시각의 스냅샷 ID와 계산 조건을 참조한다. 실제 자동 수집 출처·연동·스케줄은 이번 시안에 연결하지 않았다.

## 12. 구별 구조와 화면 밀도 재검토

사용자는 강남구·서초구·송파구 같은 자치구가 먼저 나오고 그 아래 단지가 그룹화돼야 한다고 요청했다. 구 카드와 선택 카드가 늘어난 후 UI에 불만을 표시했다. 후속 시안은 큰 소개 영역과 중복 선택 카드를 줄이고, 왼쪽 지역·단지 목록과 오른쪽 분석 화면으로 재구성했다. 이 디자인의 사용자 수락은 아직 확인되지 않았다.

- 지역 순서는 강남구·서초구·송파구를 먼저 두고 성동구·마포구의 예시 관심 단지를 잇는다. 서울 매물 화면은 나머지 자치구도 선택할 수 있다.
- 구 전체 선택은 해당 구의 단지만 변경한다. 일부 선택은 체크박스의 중간 상태로 표현하며 다른 구의 선택을 지우지 않는다. 비교함에서 개별 제거도 가능하다.
- 워크북의 표본 조건은 표시할 단지를 좁힌다. 구 머리글의 전체 선택은 현재 표시된 단지를 대상으로 하며 해당 범위를 이름에 표시한다. 표 정렬은 구별 묶음 안에서 적용한다.
- 비교 차트와 표는 선택한 모든 구의 단지를 유지한다. 비교표는 자치구 머리글 아래 단지 열을 모으고, 구를 바꿔도 기준 단지는 선택 목록에 있는 동안 유지한다.
- 모바일에서는 구를 눌러 단지 목록을 펼치며 구 전체 선택·단지 체크·비교함 제거를 지원한다. 지표 정의는 상단에서 항상 열 수 있다.

최신 검수는 기존 기능과 구별 상태/모바일 상호작용을 포함해 44항목이다. 360~1440px 화면·실제 클릭·키보드 근거 열기·다운로드를 확인했고 JS 오류/서버 쓰기/외부 요청은 0이다. 원자료·수집 범위는 §11과 동일한 합성 예시이며 제품 화면으로 적용하지 않았다.
