# 디자인 시스템 — 둘이서은퇴

새 화면을 만들거나 고칠 때 이 문서 하나만 보면 되게 정리했다. 눈으로 보는 견본은 앱 주소 **`http://127.0.0.1:5180/#design`** (`web/src/design/DesignSystem.tsx`).

- 값의 원천: 색·글자 크기 `web/src/theme.css`, 숫자 표기 `web/src/lib/format.ts`, 컴포넌트 `web/src/components/ui/`. 이 문서에 hex를 새로 적지 않는다(아래 표의 값은 설명용 — 다르면 theme.css가 맞다).
- 근거: `docs/research/UI_REFERENCES.md`(토스 디자인 시스템 값, WCAG 대비 계산), 사용자 결정 `docs/DECISIONS.md`(2026-10-28 화면 표준), 사용자 메모 "AI 같은 디자인 금지".
- 바꾸는 법: 토큰이나 컴포넌트를 바꾸면 견본 페이지에서 확인하고 커밋 메시지에 적는다. 색·자산군 색처럼 사용자가 보는 결정은 먼저 묻는다.

## 0. 새 화면을 만들라고 할 때 (요청하는 법)

이 문서는 `CLAUDE.md` "시작할 때 읽을 것"에 들어 있어서, 이 폴더에서 일하는 Claude·Codex는 화면 작업 전에 읽는다. 요청은 이렇게 하면 된다.

> "`docs/DESIGN_SYSTEM.md` 기준으로 **[화면 이름]** 만들어줘. 들어갈 것: **[숫자·입력·버튼]**. 견본(#design)에 없는 모양이 필요하면 먼저 견본에 추가하고 보여줘."

짧게는 "디자인 시스템대로 ○○ 만들어줘"로 충분하다. 받은 쪽(에이전트)은 다음 순서로 한다.

1. 견본에 있는 컴포넌트·패턴으로 먼저 짠다 (§4·§5).
2. 없는 게 필요하면 `components/ui/`에 만들고 **견본 페이지에 한 칸 추가**한 뒤 쓴다. 화면 파일 안에서만 쓰는 1회용 스타일을 만들지 않는다.
3. 끝나면 §7 점검표를 돌리고, 결과 화면 캡처를 보여 준다.

결과가 이상하면 "견본의 ○○ 모양이랑 다르다"처럼 견본을 기준으로 말하면 고치기 쉽다.

## 1. 원칙

1. **증권사 잔고 화면·토스처럼.** 글자와 숫자가 주인공. 장식은 빼고 선과 바탕색 차이로 구역을 나눈다.
2. **숫자는 서버가 계산하고 화면은 보여 주기만.** 화면 코드에서 합계·비율을 새로 계산하지 않는다(CLAUDE.md "숫자 → 코드/DB").
3. **색 하나에 뜻 하나.** 빨강 = 상승(이익)·오류, 파랑 = 하락(손실), 초록 = 엑셀 선택. 이 색을 다른 뜻으로 쓰지 않는다.
4. **토큰 밖은 못 쓴다.** Tailwind 기본 팔레트와 글자 크기는 `theme.css`에서 지웠다. `bg-blue-500`, `text-[13px]`, `#hex`를 새 코드에 쓰지 않는다.
5. **첫 화면은 메인 대시보드**(`concept.jpg` 구조, 2026-11-07). 엑셀 워크북은 "표로 보기"로 연다. 카드형 화면은 새 표준(토큰)으로 옮기는 중이다(BACKLOG UI-MIGRATE). 대시보드 구조를 바꾸는 제안은 별도 시안으로 먼저 보여 준다.

## 2. 색 (토큰)

Tailwind 클래스는 `bg-*`, `text-*`, `border-*` 뒤에 토큰 이름을 붙인다. 예: `text-grey-600`, `bg-up-soft`, `bg-cls-stock`.

| 역할 | 토큰 | 쓰는 곳 |
|---|---|---|
| 화면 바탕 | `grey-100` | 워크북 바깥, 견본 바탕 |
| 면(카드·시트) | `white` / `background` | 표·대화상자 |
| 선 | `grey-200` (`border`) | 구역 경계, 표 줄 |
| 입력 테두리 | `grey-300` (`input`) | Input·Select |
| 비활성 글자 | `grey-500` | 꺼진 링크. 13px 본문에는 쓰지 않는다(대비 3.0:1) |
| 보조 글자 | `grey-600` (`muted-foreground`) | 설명, 표 머리, 단위 (대비 4.6:1) |
| 본문 | `grey-900` (`foreground`) | 글자, 주 버튼 바탕 |
| 상승 | `up` · 큰 숫자 `up-big` · 바탕 `up-soft` | +손익, +수익률 |
| 하락 | `down` · 큰 숫자 `down-big` · 바탕 `down-soft` | −손익, −수익률 |
| 오류·삭제 | `destructive` | 오류 문구, 삭제 버튼 |
| 엑셀 강조 | `sheet-select` · `sheet-select-soft` | 선택 칸 테두리, 현재 시트 탭 — **여기만** |
| 엑셀 격자 | `sheet-line` · `sheet-head` · `sheet-head-text` | ReadGrid·편집 시트 |
| 입력 칸 | `input-soft` | 시트 안 사람이 넣는 칸(이번 달 납입·결정 사유) |

**상승·하락 단계:** 13~17px 숫자는 `up`/`down`(700 단계), 22px 이상 큰 숫자는 `up-big`/`down-big`(500 단계). 색만으로 구분하지 않게 숫자에는 늘 부호(+/−)를 붙인다.

**자산군 9색** — `cls-stock`(주식), `cls-long-bond`(장기채), `cls-mid-bond`(중기채), `cls-gold`(금), `cls-commodity`(원자재), `cls-cash`(현금), `cls-property`(부동산), `cls-mixed`(혼합·미분류), `cls-debt`(대출). 코드에서는 `classInfo[key].color`(= `var(--cls-*)`)로 읽는다. 자산군 색은 막대·도넛·범례 점에만 쓰고 글자색으로 쓰지 않는다.

> 미결정(사용자): 주식 색(`cls-stock` 파랑)이 하락 파랑과 비슷하다. 바꿀지는 사용자 결정 — UI_REFERENCES.md.

## 3. 글자

글꼴은 Pretendard 하나. 7단계만 쓴다.

| 클래스 | 크기 | 쓰는 곳 |
|---|---|---|
| `text-3xl` | 30px | 화면에 하나뿐인 큰 합계 |
| `text-2xl` | 22px | 요약 숫자 |
| `text-xl` | 20px | 구역 제목 |
| `text-lg` | 17px | 대화상자 제목 |
| `text-base` | 15px | 본문, 로고 |
| `text-sm` | 13px | 표·버튼·입력 — 기본 |
| `text-xs` | 12px | 표 머리, 보조 설명, 힌트 |

- 굵기: 본문 400, 이름표 500(`font-medium`), 강조·합계 600(`font-semibold`), 제목 700(`font-bold`).
- 숫자: 표·목록·위아래 비교는 고정폭(`tabular-nums`, 워크북 `.wb` 안은 자동). 숫자 칸은 오른쪽 정렬.
- 11px 이하는 쓰지 않는다.

## 4. 숫자 표기

`web/src/lib/format.ts`에서 가져온다. 파일마다 `won()`·`pct()`를 새로 만들지 않는다.

| 함수 | 예 | 규칙 |
|---|---|---|
| `won(n)` | 11,239,428원 | 잔고·평가금액. 원 단위까지 |
| `won(n, {signed:true})` | +146,000원 | 손익·변화량은 + 를 붙인다 |
| `won(n, {unit:false})` | 4,623,502 | 표 칸 — 머리줄에 "(원)" |
| `manwon(n)` | 3억 1,245만원 | 문장 속 큰 금액 요약. 만원 아래 반올림 |
| `pct(n)` | +3.15% | 수익률 — 소수 2자리, 부호 |
| `pct(n, {signed:false, digits:1})` | 41.2% | 비중 — 부호 없음 |
| `pp(n)` | −1.2%p | 비중 차이 |
| `shares(n)` | 153주 | 수량 |
| 값 없음 | — | 아직 모르는 값. 0과 다르다 |
| 숨김 | •••• | 금액 숨기기 |
| `day(iso)` | 2026.11.16 | 화면 날짜. 저장은 ISO |

- 음수는 유니코드 빼기 `−`(U+2212). 하이픈 `-`보다 길어 표에서 잘 보인다.
- 색은 `tone(n)` 또는 `<Amount tone="auto">`: 양수 빨강, 음수 파랑, 0은 색 없음. 평가금액·잔고처럼 방향이 없는 숫자에는 색을 넣지 않는다.
- 표 밖 숫자 하나는 `<Amount value fmt tone big hidden/>`(`components/ui/amount.tsx`). 엑셀 시트 안은 `ReadGrid`의 `Cell`(`fmt`, `tone`).

## 5. 컴포넌트

모두 `web/src/components/ui/` (shadcn 기반, 우리 토큰으로 테마). 견본 페이지에 실물이 있다.

| 컴포넌트 | 규칙 |
|---|---|
| **Button** | 한 화면(대화상자)에 진한 주 버튼(`default`)은 하나. 나머지는 `outline`·`ghost`. 크기: 표 안 `xs`(24px), 머리줄 `sm`(32px), 대화상자 기본(36px). 아이콘은 lucide, 글자 앞 `size-3.5`. 파란 버튼 없음 |
| **Input / Select / Checkbox / Label** | 이름표는 칸 위. 금액 칸은 `inputMode="numeric"` + `text-right tabular-nums`. 오류는 `aria-invalid` + 칸 아래 `text-xs text-destructive` 한 줄(무엇이 틀렸고 어떻게 고치는지) |
| **DropdownMenu** | 머리줄 "가져오기"처럼 같은 종류 행동 여러 개를 묶을 때. 항목 앞에 아이콘 `size-4` |
| **Dialog** | 등록·확인처럼 흐름이 있는 일. 제목은 동사로 끝나는 행동("키움에서 잔고 불러오기"). 버튼은 오른쪽 아래: [닫기 outline] [주 버튼] |
| **Tabs** | 같은 화면에서 보는 대상만 바꿀 때(나·배우자·부부). 다른 일로 넘어가면 탭이 아니라 시트 탭·메뉴 |
| **Tooltip** | 용어 풀이 한 줄. 설명 카드 대신 |
| **Amount** | 표 밖 숫자 하나 (§4) |
| **ReadGrid** (`workbook/ReadGrid.tsx`) | 워크북 읽기 표. 머리 칸 `head`, 구역 제목 `section`, 칸 안 막대 `bar`(자산군 색), 입력 칸 `edit`(노란 바탕), 버튼 칸 `btn` |
| **AssetSheet** (`sheet.tsx`) | 편집용 엑셀 표(자산·보유종목 입력) |

## 6. 패턴

**화면 뼈대(워크북)**: 머리줄 48px(로고 · 파일 이름 · 사람 선택 · 가져오기 · 내려받기) → 한 줄 요약 띠 → 시트 → 아래 시트 탭 36px(현재 탭은 초록 밑줄). 새 기능은 새 화면보다 **시트 탭이나 가져오기 메뉴 항목**으로 먼저 넣는다.

**면과 그림자**: 그림자는 떠 있는 층(드롭다운·대화상자·알림)에만. 면 위 요소(입력·버튼·카드)는 선과 바탕색으로 나눈다. 모서리 6px, 엑셀 격자 안은 0.

**간격**: 4px 단위. 칸 안 8px(`px-2`), 구역 안 16px(`p-4`), 구역 사이 32px(`py-8`). 화면 양옆 최소 16px.

**덜어내기** (2026-11-18 사용자 "군더더기 빼기", 리밸런싱 시안 A에서 정함 — 모든 화면에 적용):
- **같은 숫자는 한 번만.** 문장과 막대·표가 같은 금액을 말하면 문장에서 뺀다. 문장은 진단 한 줄("장기채가 목표보다 20.0%p 적어요."), 금액은 막대·표가 말한다.
- **거의 안 바꾸는 설정은 글 한 줄 + '바꾸기'.** 운용 방식·원칙처럼 한 달에 한 번도 안 만지는 값은 버튼·고르기 칸을 늘 펼쳐 두지 않는다. 누르면 그 자리에서 펼친다.
- **할 일 없는 항목은 얇게.** 잔고 없음·범위 안처럼 할 일이 없거나 하나뿐인 줄은 한 줄 높이로. 할 일 있는 줄과 같은 크기로 두지 않는다.
- **안내 문구는 화면에 한 곳.** "등록한 잔고 기준·주문은 증권사 앱에서·추천 아님" 같은 말은 화면 맨 아래 한 줄로 합친다. 머리 오른쪽·카드 안에 다시 쓰지 않는다.
- **요약은 개수만.** 화면 맨 위 요약이 아래 카드가 할 말을 문장으로 되풀이하지 않는다("지금 옮길 계좌 1개 · 납입 때 맞출 계좌 1개").
- **자세한 건 펼쳐서.** 종목·수량, 확인 전 종목, 지난 기록, 사유 입력은 누를 때만 보인다.
- **보조 도구는 접어 둔다.** 주 화면과 따로 계산하는 도구(예: 종목 잔고 CSV 계산)는 제목+설명 한 줄로 접힌 채 아래에.
- **빈 자리를 만들지 않는다.** 문장이 한 줄로 줄면 그 옆(막대·입력)과 세로 가운데를 맞추고 카드 안 여백은 `px-5 py-4`, 카드 사이 12px.

**계좌 구분 색**: 계좌가 여러 개 나란히 나오는 화면은 계좌마다 `--acct-1..4`(진한 왼쪽 패널 + 옅은 줄 바탕). 자산군 색과 겹치지 않게 고른 값이고 테마(brand-mode)를 따라가지 않는다.

**상태 문구** (해요체, 한 문장, 느낌표·영어·기술 용어 없이):
- 불러오는 중: "불러오는 중…" + 돌아가는 아이콘
- 비어 있음: "아직 등록한 계좌가 없어요." + 할 일 버튼 하나
- 오류: 무슨 일 + 할 일. "키움 서버에 연결하지 못했어요. 인터넷 연결을 확인해 주세요." 에러 코드·영문 메시지는 그대로 보여 주지 않는다
- 완료 알림: 화면 아래 가운데 검정 띠, 3.5초. "키움 잔고를 새로 저장했어요."

**말투**: 사실과 계산 결과만. 예측·추천("오를 거예요", "이 ETF가 좋아요") 금지. 주문은 "기록만 하고 주문은 증권사 앱에서".

**반응형**: 360·390px에서 핵심 숫자가 좌우 이동 없이 보일 것. 넓은 표는 표만 가로 스크롤, 머리줄 버튼은 아이콘만 남기고 글자를 숨긴다(`hidden sm:inline`).

**하지 말 것**: 점 달린 알약 배지 · 그라데이션 아이콘/배경 · 보라 · 영문 머리글 · "왜 이렇게 했는지" 설명 카드 · 파란 버튼/링크 · 엑셀 리본·파일 제목줄 흉내 · 비공식 역추적 색.

## 7. 점검표 (화면 작업 끝낼 때)

- [ ] 새 코드에 `#hex`, `rgb(`, `text-[..px]`, Tailwind 기본 색 이름이 없다
- [ ] 숫자 표기는 `lib/format.ts`·`Amount`·`ReadGrid` 중 하나로만
- [ ] 상승·하락 숫자에 부호가 있고, 방향 없는 숫자엔 색이 없다
- [ ] 주 버튼은 하나, 파란 버튼 없음
- [ ] 문구는 해요체 한 문장, 추천·예측 없음
- [ ] 360px과 1280px 화면 캡처로 확인
- [ ] 새 컴포넌트·패턴이면 견본 페이지(#design)에 추가
- [ ] §6 덜어내기: 같은 숫자 두 번 없음 · 안내 문구 한 곳 · 안 바꾸는 설정은 접힘 · 할 일 없는 줄은 얇게

## 8. 아직 정리 안 된 것
