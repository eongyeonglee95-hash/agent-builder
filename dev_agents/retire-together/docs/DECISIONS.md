- 각 구 ‘주목’은 거래·비교 표본이 규칙의 최소치를 충족하고, 유사 단지보다 낮게 관측된 후보 중 상대 가격 차이가 가장 큰 한 곳에만 표시한다. 단순 최고가·AI의 근거 없는 점수로 붙이지 않는다. 해당 후보가 없으면 미표시한다.
- 연봉 입력 펼침은 PC 네 필드 한 줄, 모바일 두 열로 고정한다. 후보 영역은 연한 면, 입력 영역·후보는 밝은 면, 선택 후보는 기존 주색으로 구분한다.
- 시장·리서치 내부를 시황 / 심리·금리 / 전문가 소식으로 분리한다. 서울 구별 등락 히트맵은 실제 가격 지표이므로 시황에 배치할 계획이다. 현재의 관심 단지 히트맵을 서울 25개 구 데이터로 오인하지 않도록 한다.
- 사용자 정정: 리서치 세 메뉴는 하위 탭이 아니다. 상단을 ‘내 부동산 / 관심 단지 / 시황 / 심리·금리 / 전문가 소식’ 다섯 동급 메뉴로 바꾼다. 기존 시장·리서치 메뉴와 내부 중첩 탭은 제거한다. 기존 market/research 경로는 시황으로 이어진다.


### 2026-11-20 · 우리 집 KB 일반평균가 비교
- 최근 실거래 옆에 KB 일반평균가와 기준일을 표시한다. 자동 조회 연결이 없으므로 KB에서 확인한 동일 평형 매매 일반평균가를 시세·호가 관리에서 직접 기록한다. 미등록은 `—`.
- KB 기록은 비교용이며 장부·순자산 금액을 변경하지 않는다. 주소·전용면적 변경 시 기존 KB 기록을 해제한다. 집 수정과 시트 동기화에서 기록을 보존한다.
- 최근 유사 거래·이상치 제외 기반 순자산 평가 전환은 이번 KB 항목 추가와 별도로 남아 있다.

### 2026-11-20 · 후보 복수 선택과 분석 재사용
- 체크 선택과 상세 분석 열기를 분리한다. 선택한 후보는 한 번의 계획 저장으로 추가하고 실패 시 선택을 유지한다.
- 검증된 단지별 공개 장단점·출처만 로컬 서버에 보관하고 discovery.analysis_cache_days 동안 재사용한다. 소득·가용자금은 보관하지 않고 가격·필요 자금은 재조회한다. 분석 새로 갱신은 캐시를 우회한다. 정기 자동 조사 예약은 아직 별도 작업이다.
- 공백을 줄이기 위해 후보는 구별 3열 안의 소형 사각 비교 카드로 표현한다. 가격과 추가 자금만 강조하고 긴 분석은 단일 상세로 연다.

### 2026-11-20 · 후보 기본 정보와 지도 너비
- AI 후보 카드에 세대수·건축연도를 작은 한 줄로 표시한다. 건축연도는 실거래 원자료, 세대수는 단지 조사 인용문과 출처에 일치하는 숫자만 사용하며 미확인 값은 생략한다. 확인된 세대수는 분석과 함께 캐시한다.
- 관심 단지 지도는 본문 전체 너비를 사용하고, 가격 차트와 선택 단지 상세는 그 아래에 둔다.
- 지도는 선택된 관심단지 좌표에 맞춰 자동 확대한다. 전체/강남/서초/송파 필터는 지도 안에서 동작하고 비교 목록의 체크는 유지한다. 단지를 누르면 해당 위치로 확대하며 '단지에 맞추기'로 복귀한다. 지도 높이는 화면의 60%를 사용한다.
- 관심 단지의 중복 순자산·현금·연봉·PIR 설정 요약을 제거한다. 자금 설정은 내 부동산에서 관리하고 관심 단지는 지도와 단지 비교에 집중한다.
- 후보 연식은 건축연도와 경과 연수를 함께 표시한다(예: 2008년 · 18년 경과). 경과 연수는 조회 연도에서 원자료 건축연도를 뺀 값이며, 준공일을 모르는 상태에서 만 나이나 N년차로 표현하지 않는다. 미확인·미래 연도는 경과 연수를 생략한다.
- 관심 지도는 소유자별 마지막 구 선택을 세션 동안 기억한다. 구 버튼에 표시 대상 수를 함께 표시하고 중복 구 범례를 제거한다. 표시 대상이 없는 구에는 전체 관심단지로 복귀하는 동작을 제공한다. 지도 재맞춤 시 가격 라벨과 선택 강조를 유지한다.

### 2026-11-20 · 심리·금리 날짜별 조회
- 사용자: AI 최신 확인을 누르기 전부터 공식 지표·보고서를 바탕으로 시계열과 히트맵, 주간 변화를 표시하고 상단에서 일간·주간·월간과 날짜를 고른다.
- 원자료의 공표 주기는 유지한다. 주간·월간 수치를 일간 값으로 복제하지 않고, 누락 기간은 0이나 보합으로 표시하지 않는다.
- KB 공식 시계열 수집·로컬 캐시·조회 화면을 추가했다. 현재 환경의 KB 응답은 정상 JSON으로 검증하지 못했으므로 실제 수집 성공과 별개다. 금리·일간 공급원, 부동산원 수급지수, 개별 보고서 날짜별 연결은 후속 과제다.
- 추가 문구 요청: 단지 후보의 `준공연도 · N년 경과`를 `준공연도 (N년차)`로 표시한다. 연수 원값은 유지하며 0년은 `(신축)`으로 표시한다.

### 2026-11-20 · 주식 화면 중복 자산 내역 제거
- 사용자 요청으로 주식 화면의 ‘등록한 주식형 자산’ 요약과 ‘등록한 자산 내역 · 금액 갱신’ 영역을 제거한다. 보유 주식 표는 유지하고 자산 원장은 우리 자산에서 관리한다.
- 하락 원인 AI 분석은 논의 중인 후속 기능이며 이번 제거 작업에 추가하지 않는다.
### 2026-11-20 · 버튼 가독성을 공통 디자인 기준으로 유지
- 사용자 요청: 검은 버튼에 검은 글자가 보인 문제의 수정 기준을 디자인 시스템에 반영하고 이후 화면에도 적용한다.
- 공통 Button의 배경·전경 토큰을 한 쌍으로 유지하고, 화면별 초기화 CSS에서 공통 버튼을 제외한다. 비활성·저장 중을 포함한 상태별 가독성을 디자인 점검표와 개발 지침에 명시한다.

### 2026-11-20 · 가계부 (월 합계 · 돈의 흐름)
- 사용자: 부부 수입·지출을 가계부로 관리한다. 월별·연별로 끊어 보고, 우리 가계의 돈이 실제로 어떻게 움직이는지 보이게 한다. 시안(돈의 흐름·지출·수입 탭)을 확정하고 디자인 시스템에 맞춰 진행한다.
- 수입은 급여명세서 사진을 찍어 주면 Claude가 정리한다. 지출 관리가 핵심이다.
- Claude 기본값(사용자 변경 가능): 건별이 아니라 **월 합계**로 적는다. 수입은 사람별, 지출은 가구 합계. 분류는 고정비 5·생활비 7·큰 지출(그달 이름+금액)·모은 돈(연금 납입·대출 원금, 나머지는 현금 주머니) — `rules/household_book.yaml`. 새 달은 지난달 값을 미리 채우고 큰 지출만 비운다. 평균보다 15% 넘게 쓴 항목은 빨간 글씨.
- 로컬 장부와 공유 시트(기록 종류 `household_month`, 가구 공동) 모두에 저장한다. 명세서 파일 자동 분류·급여명세서 사진 읽기·은퇴 계획 연결은 BACKLOG HB-01 후속 단계.

### 2026-11-20 · 가계부를 1년 표 + 흐름으로 (HB-02)
- 사용자: "가계부 너무 어렵다, 표로 관리돼야 한다", "캡처 떠서 올리면 자동 분류", "매달 정기적으로 넣는 것들은" 고정으로, "진짜 심플하게, 수입·지출 합계가 흐름으로 흐르는 느낌". 시안(1년 표·캡처 자동 분류·매달 고정)을 확정.
- 화면: 위에 고른 달의 합계 3개와 돈의 흐름 그림, 아래에 엑셀처럼 칸을 눌러 고치는 1년 표(최근 6달 + 월평균, 단위 만원). 월별/연별·지출/수입 탭과 달 적기 양식은 없앴다.
- 매달 고정: 칸마다 체크해 두면 새 달이 열릴 때 지난 금액으로 미리 채우고 회색으로 보인다(고치면 검은 글씨). 최근 3달 금액이 같으면 고정을 권한다. 고정 목록은 달 기록 안(`fixed`)에 둬서 공유 시트에도 같이 간다.
- 캡처: 카드·은행 이용내역 캡처 → 비전은 날짜·가맹점·금액만 옮기고, 분류는 코드가 한다(전에 고른 분류 > `merchant_rules` 낱말). 모르는 건만 고르게 하고, 고른 분류는 다음 달부터 자동. 표에는 항목별 월 합계만 더하고, 같은 내역은 두 번 더하지 않는다. 캡처 이미지는 남기지 않는다.

### 2026-11-20 · 가계부 명세서 파일 올리기
- 사용자: 명세서 자동 분류를 엑셀·CSV부터 이어서 한다(Claude가 이어받음).
- 카드사·은행에서 내려받은 엑셀(.xlsx·카드사 HTML형 .xls)·CSV는 AI 없이 코드로 읽는다. 머리글 이름은 `rules/household_book.yaml` `statement_columns`, 취소·환불·입금·음수·합계 줄은 뺀다. 분류와 확인 표·중복 방지는 캡처와 같은 흐름을 쓴다. 진짜 옛 .xls(바이너리)는 .xlsx·CSV로 다시 저장하도록 안내한다.

### 2026-11-23 · 미국 주식 퀀트 보드 시안
- 사용자 요청: 미국 주식 중심, 간단한 상단 매크로 지표, S&P 500/나스닥 히트맵, 퀀트 투자 지향을 반영한 복수 시안.
- 별도 `web/public/previews/stock-quant/index.html`에서 A 시장 지도 / B 계좌 진단 / C 규칙 점검을 비교한다. 모든 데이터·분석은 가상이며 실제 시세·뉴스·AI·계좌 저장과 미연결이다.
- 지수 전환·보유 필터·종목 상세·하락/비중 기준 변경·일시적 점검 기록을 시안에서 체험한다. 실제 주식 화면 적용은 방향 선택 후 진행한다.

### 2026-11-23 · 주식 보드 B+A 적용
- 사용자 선택: B 계좌 진단 + A 시장 지도. 실제 주식 화면을 매크로 → 수익·집중도 → 시장 히트맵 → 보유 주식 → 하락 원인 점검 순서로 구성한다.
- 매크로는 Yahoo Finance 공개 시세와 항목별 KST 기준 시각을 표시한다. TradingView 지수 위젯의 일부 심볼 미지원으로 상단은 자체 표시하며 히트맵만 TradingView 공개 임베드를 사용한다. 시세 지연·외부 위젯 색상 범례를 표시한다. 보유정보를 외부 위젯에 보내지 않는다.
- 집중도는 등록 일반계좌 주식 기준이며 예수금·ETF 내부 보유는 포함하지 않는다. 같은 종목은 계좌 간 합산한다. 부분 시세만으로 전체 전일 수익률이나 하락 기여도를 표시하지 않는다.
- 동일 기간 가격·입출금 이력이 없는 지수 비교·현재/최대 낙폭, 뉴스·공시 원문이 없는 AI 원인 분석은 미연결로 표시한다. 하락 기준은 화면 안에서만 변경하며 자동 주문·자동 AI 실행·영구 저장을 하지 않는다.
- TradingView 히트맵은 S&P 500/나스닥 100을 전환하며 보유 종목 강조는 제공하지 않는다. 실제 시세·히트맵 렌더링과 API 실패/빈 계좌/하락 조건/모바일을 확인한다.

### 2026-11-23 — 전체 화면 공통 디자인 적용
- 사용자 요청으로 전체 화면의 공통 디자인 적용 여부를 조사하고 구형 동작 버튼·일반 입력·선택창을 공통 컴포넌트로 이전한다.
- 화면 구조와 기능은 유지한다. 표 셀 편집기와 지도·차트 등 전문 컨트롤을 일반 폼으로 강제 변환하지 않는다.
- `NativeSelect`를 디자인 견본에 추가해 기본 HTML 폼 동작을 유지하며 선택창의 토큰을 통일한다. 잔여 개별 색상과 검증 한계는 `reviews/design-system-2026-11-23.md`에 기록한다.
