# 사주 리서치·학습

목표는 자료를 많이 쌓는 것이 아니라, 기존 조사에서 아직 답하지 못한 질문에 근거를 더하고 사람이 해석 결과를 검토할 수 있게 돕는 것이다.

## 프로젝트 맥락

이 스킬의 프로젝트 루트는 두 단계 위 `dev_agents/saju/`다. 다른 프로젝트로 옮겼다면 그 프로젝트의 결정 기록과 자료 위치를 먼저 찾는다.

1. [README](../../README.md)의 사용자 결정, [협업 인계](../../CODEX_HANDOFF.md)의 담당·수신 상태를 읽는다.
2. [위키 목차](../../wiki/README.md)와 `research/` 파일 제목을 검색하고, 질문에 해당하는 절만 읽는다. 모든 위키 페이지를 매번 다시 읽거나 재작성하지 않는다.
3. 책·공부 질문이면 [도서·학습 로드맵](../../research/08_명리도서_학습로드맵.md)을 확인한다. 최신 순위가 필요한 경우 조사 당시의 순위를 현재 순위로 재사용하지 않는다.

사용자 최신 지시와 승인된 결정을 우선한다. `wiki/`의 초안, "우리 적용" 후보 YAML, 연구자의 학설을 제품의 승인 규칙으로 승격하지 않는다. 결정끼리 충돌하거나 실제 구현이 달라지면 관련 경로·문구·상태를 적고 필요한 범위만 확인한다.

## 중복 없는 조사

검색 전에 질문별로 `기존 경로 → 확인 수준 → 이번에 부족한 것`을 짧게 정리한다. 같은 출처를 여러 곳에서 재인용한 것은 독립 근거로 세지 않는다.

| 기존 상태 | 다음 행동 |
|---|---|
| 질문에 답하는 확인된 근거가 있고 시점도 적절함 | 해당 절을 연결하고 재조사하지 않음 |
| 검색 결과·목차·초록만 있음 | 필요한 주장에 한해 원문·본문을 확인 |
| 수치·순위·제품 기능이 오래됨 | 원출처에서 현재 기간을 확인하고 변경분 기록 |
| 학파·출처·승인 결정 사이 차이가 있음 | 견해를 분리해 비교하고 적용 결정과 구분 |
| 관련 자료가 없음 | 범위를 좁혀 새 조사 |

논문 주장을 조사하면 실제 연구 방법·표본·비교 조건·한계를 확인한다. 초록만 읽었으면 초록 확인이라고 쓴다. 다른 점술 체계의 연구를 사주 예측력의 직접 증거로 바꾸거나, 관찰 상관관계를 원인으로 단정하지 않는다.

각 근거에는 제목·저자/기관·게시 또는 출간일·URL·확인일·확인 범위를 남긴다. 확인 범위는 `본문`, `발췌`, `목차/소개`, `초록`, `검색 결과만`, `미확인` 중 실제 열람 수준으로 쓴다. 접근 실패는 그대로 남기고 제목이나 검색 요약으로 빈 내용을 채우지 않는다.

새로 확인할 수 있는 질문에 답하고 남은 불확실성을 특정했으면 조사를 마친다. 무관한 자료나 비슷한 책을 계속 늘리지 않는다.

## 도서 목록과 공부 순서

- **인기도**는 서점명·분야·집계 기간·순위로, **학습 적합성**은 목차·소개·독자의 목표에 대한 판단으로 각각 근거를 붙인다. 별점·리뷰 수·서점 판매지수는 실제 판매 부수나 예측 정확도가 아니다.
- 서점 목록에 주역·타로 등이 섞여 있으면 명리 교재와 구분한다. 제외해도 원래 순위를 다시 매기지 않는다. 교차 서점 확인이 안 되면 한 서점의 관측이라고 밝힌다.
- 같은 제목의 개정판·전자책·세트·동명서를 구분한다. 가능한 경우 ISBN과 출간일을 함께 확인한다. 출간일과 순위 기간이 맞지 않으면 예약판매 여부 등을 추정 사실로 쓰지 않는다.
- 책 전문을 읽지 않았으면 독후 평가인 듯 말하지 않는다. 공개 목차·책 소개에 근거한 추천임을 밝힌다. 권수·가격·난이도·독서 시간은 확인값과 제안을 구분한다.
- 초심자에게는 먼저 읽을 **주교재 한 권**, 필요할 때 펼칠 **참고서 한 권**을 제안한다. 이미 가진 책·학습 수준이 드러나면 그에 맞춘다. 여러 입문서를 모두 완독하도록 요구하지 않는다.
- 기본 학습 경로는 `원국·일간·오행 → 십신·합충·지장간 → 강약·용신·학파 차이 → 대운·세운·월운`을 참고하되, 사용자의 목표에 맞춰 줄인다. 각 단계는 읽을 범위와 스스로 설명하거나 비교할 결과물로 제시한다. 기간은 숙달 보장이 아닌 일정 예시다.
- 에이전트 제작자는 최소한 계산 결과·해석 규칙·표현 문장의 차이를 판별할 수 있어야 한다. 간지·절입시각을 암산하거나 고전 전권을 먼저 읽을 필요는 없다.

## 해석 근거를 다룰 때

명리는 전통 해석 체계로 기술하고, 계산 일치·해석의 내부 일관성·사용자 만족·실제 예측 타당성을 구분한다. 계산이 재현되거나 앱 두 곳과 같다고 미래 사건이 검증된 것은 아니다.

- 계산 정책(달력·시간대·출생시각·절입·자시 경계)과 해석 학설(억부·조후·격국)을 분리한다. 상세 계산은 [계산엔진 조사](../../research/03_계산엔진_라이브러리.md)를 필요한 부분만 확인한다.
- 예시 명식과 연·월 간지는 검증된 계산 출력이 있을 때만 사용한다. 시각 모름을 임의의 시각으로 채우지 않는다. 검증 출력이 없으면 구조만 설명한다.
- 연운·월운은 [신년운세 초안](../../wiki/judgment/annual-fortune-method.md)을 참고하되, 절기와 양력 달력의 경계, 원국·대운·세운의 적용 조건을 드러낸다. 초안의 점수·가중치는 설계 제안이며 원전의 공식이나 승인값으로 소개하지 않는다.
- 학파가 갈리는 규칙은 `출처/판본 → 적용 조건 → 해석 → 프로젝트 채택 상태`로 비교한다. 익숙한 설명 한 가지로 차이를 숨기지 않는다.
- 건강·사망·이혼·재산 손실 같은 실제 사건을 명리 규칙만으로 확정하지 않는다. 전통적 주제와 사용자가 선택할 수 있는 일반적인 대응을 연결하되 결과를 보장하지 않는다.
- 현대 책·번역·상용 서비스의 문장을 리포트나 지식 저장소에 통째로 복제하지 않는다. 공개 목차·소개 확인, 허용된 발췌, 자신의 요약을 구분한다. 도서 추천과 해당 책을 자동 수집·학습에 이용할 권한은 별개다.

## 공유와 결과 보고

기존 Claude 담당 파일은 먼저 인계 상태를 확인한다. 기존 경로 수정이 합의되지 않았다면 별도 조사·정정 메모로 남기고 그 파일을 연결한다. 공유 문서 작성, 직접 전달, 실제 수신, 검토 완료는 서로 다른 상태다. 다른 에이전트의 답변을 기존 Claude의 답변이라고 부르지 않는다.

결과는 사용자가 먼저 할 일부터 설명한다. 도서 비교에는 제목·저자·용도·우선순위·출처가 보이게 하고, 기존 조사에서 달라진 내용과 미확인 사항을 짧게 덧붙인다. 저장할 때는 이 저장소의 문서·변경 이력 규칙을 따른다.

리서치와 스킬 검증을 앱의 완성도로 환산하지 않는다. 이번 작업에 화면·데이터 연결·실행 구현이 없다면 해당 항목은 수행하지 않았다고 명시한다.
