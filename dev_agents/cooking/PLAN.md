# 오늘의 식탁 — 기획 정리 (v0.1 기준)

원본: [오늘의 식탁 — 가족일정형 요리 서비스 상세 기획 v0.1](https://app.notion.com/p/v0-1-4072d2f5eb90813b8a4df2d3c000ff23) (2026-10-28 초안)
노션 문서는 문장마다 [사실]·[가정]·[검증]을 붙여 두었다. 여기서는 가정과 검증 항목만 따로 표시한다.

## 1. 한 줄 가치 제안

우리 가족이 팔로우한 전문가의 요리를, 수리가 가족 일정에 맞는 때에만 골라주고 장보기·분담·변경까지 이어주어, "오늘 뭐 먹지"의 부담을 가족이 함께 나눠 지게 한다.

| 누가 | 무엇에 답하나 |
| --- | --- |
| 전문가 | 무엇을 만들지 |
| 수리 | 우리 가족에게 언제, 왜 필요한지 |
| 가족 | 누가 할지 (스스로 정함) |

쓰지 않는 표현: "영양 보충", "이번 주 미션", "아직 안 하셨어요". 주말은 "평일에 잘 안 쓰던 재료로, 가족이 함께" 정도로만.

## 2. 전문가 콘텐츠

- 상세 데이터는 노션 [전문가 마스터 DB](https://app.notion.com/p/a2e511f957f94c85be482550b612a09e). 실명 전문가는 모두 **제휴 미확정 후보**다.
- 초기안 (가정): 평일 집밥·반찬 1명 + 주말 가족식·아이밥상 1명을 핵심으로, 유명인 1명을 '이름 때문에 팔로우하는가' 검증용으로 둔다.
- 권리: 판권 구매가 아니라 전문가별 레시피 30~50개, 6개월, 사내 베타 참여자만 보는 **기간 한정·비독점 이용허락**. 학습은 제외.
- 협의 전 베타 데모는 **레시피 제목·메타데이터·공개 원문 링크만** 쓴다. 본문·사진은 쓰지 않는다.
- 출처 없는 메뉴는 '수리의 제안'으로 따로 표시하고 전문가 이름을 붙이지 않는다.
- 시안의 실명 유사 얼굴은 성명·초상 문제가 될 수 있다 (검증). 베타 시안은 가명('한식 전문가 A')과 중립 일러스트 권장.

### 분류 태그 (레시피 하나에 축별로 따로)

| 축 | 질문 | 예시 값 |
| --- | --- | --- |
| 식사 장면 | 언제 먹나 | 평일 저녁, 주말 가족식, 가족 모임·손님, 도시락, 아이 식사 |
| 메뉴 역할 | 상에서 무슨 자리 | 메인, 반찬, 밑반찬, 국·찌개, 한그릇 |
| 요리 장르 | 어느 나라 음식 | 한식 가정식, 중식, 일식, 양식, 베이킹, 유아식 |
| 함께 먹는 입맛 | 누구 입맛 | 아이(덜 맵게), 어르신, 어른(매운맛), 모두 같이 |
| 시간·노력 | 얼마나 힘드나 | 15/20/30/60분+, 재료 수, 난이도 3단계 |
| 준비 방식 | 어떻게 만드나 | 미리 만들기, 당일, 원팬, 에어프라이어, 밥솥 |
| 함께 요리 | 같이 만들 수 있나 | 아이 참여, 두 사람 분담, 혼자가 편함 |
| 계절·주재료 | 무엇으로 | 제철 월, 돼지·소·닭·생선·두부·채소 |
| 제약 (안전) | 먹어도 되나 | 알레르기 재료, 맵기 3단계 |

태그 출처는 '원문'·'추정'·'검수'로 기록. 제약 축은 원문 재료 목록에서만 만들고, 모르면 '미확인'으로 두어 필터를 통과시키지 않는다.

## 4. 시나리오 3개 (같은 가족의 한 주)

### A. 평범한 평일 저녁
- **계기**: 일요일 20:30 미리보기 (평일 제안은 이 한 번으로 묶음)
- **흐름**: 집밥 가능성이 높은 날 3일만 고름 → 날마다 전문가 1명 + 고른 이유 한 줄 → 3일치 장보기 하나로 합침 → 담당 제안 → [캘린더에 담기] 한 번 확인
- **문구**: "이번 주 저녁, 3번만 같이 정해볼까요?" / "일정만 보고 골랐으니 실제와 다르면 바꿔 주세요. 나머지 날은 비워 둘게요."
- **포인트**: 조리 시간 원문 미표기면 "수리 추정 약 25분". 요리 3번이 한 사람에게 몰리면 "목요일을 민준님께 부탁해 볼까요?". 카드마다 [이날은 간편하게].

### B. 갑자기 계획이 바뀐 날
- **계기**: 목요일 담당 민준의 캘린더에 17:00~21:00 일정이 생김 (10분 기다려 변경을 묶음)
- **흐름**: 민준 본인에게 먼저 물음 → [다른 가족에게 부탁] [시간 늦추기] [오늘은 간편하게] [그대로 할게요] → 부탁하면 지은에게 알림 → 지은이 [내가 할게요]를 누를 때만 일정 수정
- **포인트**: 다른 가족에게 먼저 "민준님이 못 와요"라고 말하지 않는다. 일정 내용은 노출하지 않는다. 기존 식사 일정 하나만 고친다(새 일정 없음). 민준의 시작 알림은 취소. 바뀐 항목만 한 번에 알림.

### C. 주말 가족 식사
- **계기**: 목요일 20:30 주말 미리보기 + '주말 한 끼 같이' 설정
- **흐름**: 시간 먼저 고름 (토 점심/토 저녁/일 저녁) → 메뉴 후보 2개, 가족 투표 → 할 일을 장보기·손질·조리·상차림으로 나누고 각자 [내가 할게요]
- **포인트**: "이번 주 계획에는 생선과 가지가 없었어요"처럼 재료만 말하고 영양은 말하지 않음. 아이 일에는 불·칼 없음. 함께 요리하는 시간 일정은 선택 사항. 반찬 더 만들기는 기본 꺼짐.

## 6. 수리의 제안·보류·침묵 원칙

- 먼저 말을 거는 건 **주 2회** (일요일 평일 미리보기, 목요일 주말 미리보기). 그 외에는 확정한 계획이 흔들릴 때만.
- 전문가를 몇 명 팔로우하든 알림 수는 늘지 않는다. 새 레시피는 다음 미리보기 후보로만.
- 집밥 가능한 날이 없으면 침묵 ("이번 주는 쉬어갈게요" 한 줄). 빈 캘린더를 여유로 보지 않는다.
- 담당자 일정이 겹치면 본인에게 먼저. 같은 끼니가 30분 안에 여러 번 바뀌면 마지막 상태만.
- 응답 없으면 요청한 사람에게만 한 번. 재촉·실패 취급 없음. 2주 연속 안 열면 빈도를 한 번 물음.
- 알레르기를 원문으로 확인 못 하면 빼거나 "원문 재료를 확인해 주세요". 아이 연령 미설정이면 이유식·유아식 노출 안 함.
- 영양·건강 질문에는 일반 정보만, 진단하지 않음.
- 알림 예산 (가정): 1인당 먼저 보내는 알림 주 2회, 변경 알림은 하루 1회로 묶음.

## 7. 데이터 관계

식사 계획 하나가 중심이고, 캘린더에는 식사 일정만 보인다. 준비 시간은 식사 계획 안의 값, 장보기는 주 1개 할 일.

| 객체 | 상태 |
| --- | --- |
| 식사 계획 (날짜·끼니·시각·인원·메뉴·준비 시작) | 제안 · 확정 · 간편하게 · 외식 · 쉬기 · 취소 |
| 메뉴 (출처 유형: 원문 / 수리 제안 / AI 변경안) | 선택됨 · 교체됨 |
| 캘린더 식사 일정 | 식사 계획을 따라감 (1:0..1) |
| 주간 장보기 목록 | 준비 중 · 주문함 · 받음 |
| 역할 | 제안 · 수락 · 거절 · 만료 |
| 알림 (묶음 키: 가족·날짜·끼니) | 예약 · 발송 · 취소 |

연쇄 규칙: 시간 변경→시작 알림 이동 / 인원 변경→안 산 항목 수량만 / 담당 변경→이전 담당 알림 취소 / 메뉴 교체→안 산 항목 교체, 산 것은 유지 / 간편하게·외식→이 끼니만 쓰는 안 산 항목 제거, 준비 알림 모두 취소.

## 8. MVP 범위

목표 (가정): C안 하나를 모바일 웹 프로토타입으로 만들어 오픈베타 '디지털 프로덕트' 트랙에 링크·평가형(Plan B)으로 올린다. A·B·C 선호는 먼저 '아이디어' 트랙 투표로 확인. 일정: 2026-12-15 개발·사전검증, 2027-01-12 전사 오픈.

| 영역 | MVP | 이후 |
| --- | --- | --- |
| 가족·캘린더 | 가상 가족·가상 캘린더, 구성·조리 시간만 바꿔보기 | 실제 캘린더, 배우자 초대 |
| 수리 | A·B·C 판단 규칙과 문구. LLM은 설명 문장·질문 응답만 | 자동 감지, 가족별 학습 |
| 전문가 콘텐츠 | 2~3명 레시피 제목·메타데이터·공개 링크 | 이용허락 후 원문 RAG, 사진 |
| 메뉴 | 인원·시간·도구·제약 필터, 인분 환산 | 대체 재료 |
| 장보기 | 합친 목록, 집에 있음 체크, 복사 | 배송 앱 연동 |
| 역할 | 제안·수락 (가상 배우자 응답) | 실제 가족 간 요청 |
| 변경 | B 한 가지 + 시간·인원 변경 | 아이 일정 변경 |
| 피드백 | S10 세 가지 | 실제 조리 시간 학습 |
| 측정 | 플랫폼 복귀 평가 + 내부 이벤트 기록 | 공통 로거(Plan A) |

MVP에서 하지 않는 것: 실제 가족 일정 수집, 건강·알레르기 실데이터 저장, 결제·주문, 전문가 원문 본문 노출, 모델 학습.

## 9. 오픈베타 검증

**1단계 아이디어 트랙**: A·B·C 중 우리 가족 저녁에 가장 도움될 안, 안별 부담 감소 0~100, 팔로우 방식 필요 여부, 가족과 나눠 쓰고 싶은 기능. 대상은 30~40대 맞벌이 임직원 (임직원 선호 ≠ 고객 수요임을 함께 적음).

**2단계 디지털 프로덕트 트랙 과업**

| 과업 | 시나리오 | 완료 기준 |
| --- | --- | --- |
| T1 이번 주 저녁 정하기 | A | 식사 2~3개 + 장보기 목록 확정 |
| T2 배우자에게 하루 부탁 | A | 담당 제안 → (가상) 수락 확인 |
| T3 야근으로 바뀐 저녁 고치기 | B | 담당·인원 변경, 이전 알림 사라짐 확인 |
| T4 주말 한 끼 정하기 | C | 시간 → 메뉴 → 역할 순 확정 |
| T5 이번 주 쉬기 | 공통 | 쉬기 선택, 알림 멈춤 확인 |

**가설** (판정 기준은 모두 후보, 검증 필요)
- H1 메뉴 결정 부담이 준다 — T1 중앙값 3분 이내, 70점 이상
- H2 실제로 할 수 있는 계획이다 — 설정 시간 초과 레시피 0건
- H3 가족 간 분담이 쉬워진다 — 담당이 한 사람에게 몰리지 않음
- H4 불필요한 알림이 적다 — 주 2회 이내, '많다' 20% 미만
- H5 일정 변경에 쉽게 대응한다 — 남은 옛 알림 0건, 이해도 80% 이상
- H6 전문가 팔로우가 신뢰·재방문 이유가 된다

**남길 이벤트**: 제안 노출·열기, 메뉴 선택·교체, 장보기 생성, 집에 있음 체크, 담당 제안·수락·거절, 캘린더 담기, 계획 변경(유형), 알림 예약·취소, 쉬기, 출처 보기, 피드백. 가족 이름·일정 본문·대화 원문은 수집하지 않는다.
